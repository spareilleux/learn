## The three tools

| Rust | Role | C# | Java |
|---|---|---|---|
| `rustup` | installs and updates toolchains | .NET SDK installer / [`global.json`](https://learn.microsoft.com/dotnet/core/tools/global-json) | [SDKMAN!](https://sdkman.io/), JDK installers |
| `cargo` | build, run, test, add dependencies | [`dotnet` CLI](https://learn.microsoft.com/dotnet/core/tools/) | [Maven](https://maven.apache.org/) / [Gradle](https://gradle.org/) |
| [crates.io](https://crates.io/) | public package registry | [NuGet](https://www.nuget.org/) | [Maven Central](https://central.sonatype.com/) |
| `rustc` | the compiler (Cargo calls it for you) | [Roslyn](https://learn.microsoft.com/dotnet/csharp/roslyn-sdk/) (`csc`) | [`javac`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html) |

## Installing

Rust is installed with [rustup](https://rustup.rs) on every OS. Rust uses the platform's **linker**, so each OS also needs its native C build tools.

<Tabs syncKey="os">
<TabItem label="Windows">

```powershell
winget install Rustlang.Rustup
```

Or download `rustup-init.exe` from [rustup.rs](https://rustup.rs). The default toolchain targets MSVC, so you also need the **[Visual Studio C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)** (the linker); `rustup-init` offers to install them if they are missing. Open a new terminal afterwards so `cargo` is on the `PATH`.

</TabItem>
<TabItem label="Linux / WSL">

```bash
sudo apt install build-essential        # the C linker (Debian/Ubuntu; use your distro's package otherwise)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"                    # or open a new shell
```

**On WSL**, install Rust *inside* the Linux distribution, not through the Windows installer, and keep your projects in the Linux file system (`~/src/...`), not under `/mnt/c`: builds are much faster there. [VS Code](https://code.visualstudio.com/docs/remote/wsl) and [RustRover](https://www.jetbrains.com/rust/) can open a WSL folder directly.

</TabItem>
<TabItem label="macOS">

```bash
xcode-select --install                  # the Apple command-line tools, which include the linker
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"                    # or open a new terminal
```

</TabItem>
</Tabs>

Then, on any OS:

```bash
rustc --version   # rustc 1.94.0 (4a4ef493e 2026-03-02)
cargo --version   # cargo 1.94.0 (85eff7c80 2026-01-15)
rustup update     # upgrade to the latest stable
```

:::note[No runtime to install]
Rust compiles to a native executable. There is no CLR or JVM to ship: the release build of "Hello, world!" is a single file: about 130 KB as a Windows `.exe`, and about 430–460 KB on macOS and Linux (measured by the course's CI).
:::

The Linux and macOS outputs come from the course's CI runners, which use a newer Cargo that adds the `note:` line.

`cargo new` also runs `git init` and writes a `.gitignore`. The layout:

```text
hello/
├── Cargo.toml      ← like .csproj or pom.xml
├── src/
│   └── main.rs     ← entry point (a library would have src/lib.rs)
└── .gitignore
```

```toml
# Cargo.toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
```

```rust
// src/main.rs
fn main() {
    println!("Hello, world!");
}
```

- `println!` ends with `!` because it is a **macro**, not a function (it checks the format string at compile time).
- The **edition** (`2024`) is like [`<LangVersion>`](https://learn.microsoft.com/dotnet/csharp/language-reference/configure-language-version) or [`--release`](https://openjdk.org/jeps/247): it opts into language changes without breaking older crates, which keep compiling with their own edition.

:::note[Outputs in this course]
Compiler errors and program outputs in the lessons were captured on Windows. On Linux and macOS they are identical except for paths: `/` instead of `\`, and no `.exe` or `.dll` extension. Every example is also built and run on Linux and macOS by the course's CI.
:::

## Everyday commands

| Task | Cargo | dotnet | Maven |
|---|---|---|---|
| New app | `cargo new app` | `dotnet new console` | `mvn archetype:generate` |
| New library | `cargo new --lib lib` | `dotnet new classlib` | — |
| Fast type-check | `cargo check` | — | — |
| Build (debug) | `cargo build` | `dotnet build` | `mvn compile` |
| Build (release) | `cargo build --release` | `dotnet build -c Release` | `mvn package` |
| Run | `cargo run` | `dotnet run` | `mvn exec:java` |
| Test | `cargo test` | `dotnet test` | `mvn test` |
| Add dependency | `cargo add rand` | `dotnet add package` | edit `pom.xml` |
| Format | `cargo fmt` | [`dotnet format`](https://learn.microsoft.com/dotnet/core/tools/dotnet-format) | [Spotless](https://github.com/diffplug/spotless) plugin |
| Lint | [`cargo clippy`](https://doc.rust-lang.org/clippy/) | [Roslyn analyzers](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/overview) | [Error Prone](https://errorprone.info/), [SpotBugs](https://spotbugs.github.io/) |
| API docs | `cargo doc --open` | [XML docs](https://learn.microsoft.com/dotnet/csharp/language-reference/xmldoc/) + [DocFX](https://dotnet.github.io/docfx/) | [`javadoc`](https://docs.oracle.com/en/java/javase/25/javadoc/) |

:::tip[Use `cargo check` constantly]
`cargo check` runs the whole type and borrow checker but skips code generation. It is much faster than a build, and it is what your editor ([rust-analyzer](https://rust-analyzer.github.io/)) does on every keystroke.
:::

## Dependencies

```bash
cargo add rand
```

```toml
[dependencies]
rand = "0.10.2"
```

- `"0.10.2"` means **compatible with 0.10.2** ([SemVer caret](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#caret-requirements)), not "exactly 0.10.2".
- The exact resolved versions are written to [`Cargo.lock`](https://doc.rust-lang.org/cargo/guide/cargo-toml-vs-cargo-lock.html) — like [`packages.lock.json`](https://learn.microsoft.com/nuget/consume-packages/package-references-in-project-files#locking-dependencies) or a [Gradle lockfile](https://docs.gradle.org/current/userguide/dependency_locking.html). Commit it for applications.
- Debug and release builds land in `target/debug` and `target/release` (like `bin/Debug` and `bin/Release`).

## Key takeaways

- `rustup` manages compilers, `cargo` does everything else, crates.io hosts packages.
- Each OS needs its native linker: Visual Studio Build Tools, `build-essential`, or the [Xcode command-line tools](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools/).
- `Cargo.toml` + `Cargo.lock` ≈ `.csproj` + lockfile / `pom.xml`.
- `cargo check` for fast feedback, `cargo build --release` for optimized binaries.

## Exercises

1. Create a project called `dice`, add the [`rand`](https://docs.rs/rand) crate, and find in `Cargo.lock` which version was actually resolved.

<details>
<summary>Solution</summary>

<Tabs syncKey="os">
<TabItem label="Windows">

```powershell
cargo new dice
cd dice
cargo add rand
cargo build
Select-String -Path Cargo.lock -Pattern 'name = "rand"' -Context 0,1
```

</TabItem>
<TabItem label="Linux / WSL">

```bash
cargo new dice
cd dice
cargo add rand
cargo build
grep -A1 'name = "rand"' Cargo.lock
```

</TabItem>
<TabItem label="macOS">

```bash
cargo new dice
cd dice
cargo add rand
cargo build
grep -A1 'name = "rand"' Cargo.lock
```

</TabItem>
</Tabs>

`Cargo.toml` holds the requirement you asked for; `Cargo.lock` holds the exact version (and every transitive dependency) that was chosen.

</details>

2. What is the difference between `cargo check` and `cargo build`, and when would you use each?

<details>
<summary>Solution</summary>

`cargo check` type-checks and borrow-checks without producing a binary, so it is fast — use it while editing. `cargo build` also generates machine code — use it when you need to run the program, and `cargo build --release` for an optimized version.

</details>
