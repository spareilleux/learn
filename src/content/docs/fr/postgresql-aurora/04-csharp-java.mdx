## Se connecter

En .NET, une [`NpgsqlDataSource`](https://www.npgsql.org/doc/basic-usage.html) contient une chaîne de connexion et son pool. Une application en crée une par base et la garde, souvent comme singleton dans l'injection de dépendances ; les objets `NpgsqlConnection` en viennent ([`Db.cs`, lignes 8-13](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/Db.cs#L8-L13), [`L04.cs`, lignes 10-21](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L10-L21)) :

```csharp
    public static string ConnectionString =>
        Environment.GetEnvironmentVariable("PG_CONNECTION")
        ?? "Host=localhost;Port=5432;Username=postgres;Password=learn;Database=learn;Application Name=learn-csharp";

    public static NpgsqlDataSource DataSource(string? extra = null) =>
        NpgsqlDataSource.Create(extra is null ? ConnectionString : $"{ConnectionString};{extra}");

    public static async Task Connect()
    {
        // Un NpgsqlDataSource par base pour toute l'application : c'est lui qui possède le pool de connexions
        await using var dataSource = Db.DataSource();
        await using var command = dataSource.CreateCommand(
            "SELECT current_user, current_setting('server_version'), (SELECT count(*) FROM ci.runs)");
        await using var reader = await command.ExecuteReaderAsync();
        await reader.ReadAsync();
        Console.WriteLine($"user: {reader.GetString(0)}");
        Console.WriteLine($"server: {reader.GetString(1)}");
        Console.WriteLine($"runs: {reader.GetInt64(2)}");
    }
```

```text
user: postgres
server: 18.6 (Debian 18.6-1.pgdg13+2)
runs: 125
```

En Java, [`DriverManager`](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/DriverManager.html) ouvre une nouvelle connexion à chaque appel, à partir d'une URL ([`L04.java`, lignes 35-49](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L35-L49)) :

```java
    static void connect() throws SQLException {
        try (Connection connection = DriverManager.getConnection(url());
             Statement statement = connection.createStatement();
             ResultSet rs = statement.executeQuery(
                     "SELECT current_user, current_setting('server_version'), (SELECT count(*) FROM ci.runs),"
                             + " current_setting('TimeZone')")) {
            rs.next();
            System.out.println("driver: " + connection.getMetaData().getDriverVersion());
            // Le pilote règle le TimeZone de la session sur le fuseau horaire par défaut de la JVM
            System.out.println("JVM time zone: " + java.util.TimeZone.getDefault().getID() + ", session TimeZone: " + rs.getString(4));
            System.out.println("user: " + rs.getString(1));
            System.out.println("server: " + rs.getString(2));
            System.out.println("runs: " + rs.getLong(3));
        }
    }
```

```text
driver: 42.7.13
JVM time zone: America/Toronto, session TimeZone: America/Toronto
user: postgres
server: 18.6 (Debian 18.6-1.pgdg13+2)
runs: 125
```

La deuxième ligne est la première différence entre les pilotes. **pgjdbc règle le `TimeZone` de la session sur le fuseau horaire par défaut de la JVM** : il l'envoie dans le message de démarrage de la connexion, à côté de `DateStyle` ([`ConnectionFactoryImpl.java`, lignes 458-464](https://github.com/pgjdbc/pgjdbc/blob/3297557c6a8059d0d6e3522c79f0bd9a6f82ee07/pgjdbc/src/main/java/org/postgresql/core/v3/ConnectionFactoryImpl.java#L458-L464)). Chaque `timestamptz` que le serveur met en texte pour cette connexion est dans ce fuseau. `check.sh` fixe le fuseau de la JVM avec `-Duser.timezone=America/Toronto`, pour que la sortie soit la même sur toutes les machines ; l'exercice 2 le change. Npgsql n'envoie pas le fuseau du client : la session garde celui du serveur par défaut, UTC dans l'image, sauf si la chaîne de connexion règle `Timezone`.

`Application Name` et `ApplicationName` nomment la connexion dans [`pg_stat_activity`](https://www.postgresql.org/docs/18/monitoring-stats.html#MONITORING-PG-STAT-ACTIVITY-VIEW) : les exemples de pools plus bas s'en servent pour compter leurs propres sessions.

## Paramètres

Les marqueurs propres à PostgreSQL sont positionnels : `$1`, `$2`. Npgsql les accepte tels quels, et aussi `@name`, qu'il réécrit en `$1` avant d'envoyer la requête. JDBC utilise `?`, que pgjdbc réécrit en `$1` ([`L04.cs`, lignes 27-53](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L27-L53), [`L04.java`, lignes 53-67](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L53-L67)) :

```csharp
        // Paramètres positionnels : $1, $2 sont ce que PostgreSQL comprend lui-même
        await using (var command = dataSource.CreateCommand("""
            SELECT run_id, started_at FROM ci.runs
            WHERE workflow_name = $1 AND started_at >= $2
            ORDER BY started_at, run_id
            LIMIT 2
            """))
        {
            command.Parameters.Add(new() { Value = "Rust course examples" });
            command.Parameters.Add(new() { Value = new DateTime(2026, 9, 13, 18, 0, 0, DateTimeKind.Utc) });
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                var startedAt = reader.GetDateTime(1);
                Console.WriteLine($"{reader.GetInt64(0)} {startedAt:O} Kind={startedAt.Kind}");
            }
        }

        // Paramètres nommés : Npgsql réécrit @os en $1 avant d'envoyer la requête
        await using (var command = dataSource.CreateCommand("""
            SELECT count(*) FROM ci.jobs WHERE labels[1] = @os AND duration > @longer_than
            """))
        {
            command.Parameters.AddWithValue("os", "windows-latest");
            command.Parameters.AddWithValue("longer_than", TimeSpan.FromMinutes(2));
            Console.WriteLine($"windows jobs over 2 minutes: {await command.ExecuteScalarAsync()}");
        }
```

```text
34776807003 2026-09-13T19:09:08.0000000Z Kind=Utc
34777004019 2026-09-13T19:12:56.0000000Z Kind=Utc
windows jobs over 2 minutes: 8
```

34777004019 2026-09-13T19:12:56Z

Les valeurs voyagent à part du texte SQL, dans le message `Bind` du protocole : pas d'injection SQL, et pas de guillemets à mal échapper. `TimeSpan` correspond à `interval`, et le paramètre nommé `@longer_than` est comparé à la colonne virtuelle `duration` de la leçon 2.

### Listes : un tableau, pas IN

`WHERE x IN (@a, @b, @c)` demande un paramètre par valeur, et une instruction différente pour chaque longueur de liste. PostgreSQL prend toute la liste comme un seul paramètre tableau ([`L04.cs`, lignes 55-66](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L55-L66), [`L04.java`, lignes 69-78](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L69-L78)) :

```csharp
        // Un paramètre tableau remplace une liste de valeurs : = ANY ($1), pas IN (...)
        await using (var command = dataSource.CreateCommand("""
            SELECT labels[1], count(*) FROM ci.jobs WHERE labels[1] = ANY ($1) GROUP BY 1 ORDER BY 1
            """))
        {
            command.Parameters.Add(new() { Value = new[] { "macos-latest", "windows-latest" } });
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                Console.WriteLine($"{reader.GetString(0)}: {reader.GetInt64(1)}");
            }
        }
```

```java
            // Un paramètre tableau : = ANY (?)
            try (PreparedStatement ps = connection.prepareStatement(
                    "SELECT labels[1], count(*) FROM ci.jobs WHERE labels[1] = ANY (?) GROUP BY 1 ORDER BY 1")) {
                ps.setArray(1, connection.createArrayOf("text", new String[] {"macos-latest", "windows-latest"}));
                try (ResultSet rs = ps.executeQuery()) {
                    while (rs.next()) {
                        System.out.println(rs.getString(1) + ": " + rs.getLong(2));
                    }
                }
            }
```

```text
macos-latest: 34
windows-latest: 35
```

Npgsql fait correspondre un `string[]` à `text[]` ; en JDBC, `Connection.createArrayOf` construit le tableau. Les équivalents SQL Server sont un paramètre table ou `STRING_SPLIT`.

### DateTime, DateTimeOffset et fuseaux horaires

Npgsql décide du type PostgreSQL d'un [`DateTime`](https://learn.microsoft.com/dotnet/api/system.datetime) d'après son `Kind`, comme le décrit sa [documentation des dates et heures](https://www.npgsql.org/doc/types/datetime.html) : `Utc` est envoyé comme `timestamptz`, `Unspecified` et `Local` comme `timestamp` sans fuseau horaire. Comparé à une colonne `timestamptz`, un `timestamp` est converti par le serveur, **dans le fuseau horaire de la session** ([`L04.cs`, lignes 68-94](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L68-L94)) :

```csharp
        // DateTime.Kind décide du type du paramètre : Utc part en timestamptz, Unspecified et Local en timestamp,
        // que le serveur convertit en timestamptz dans le fuseau horaire de la session
        foreach (var options in new[] { "Timezone=UTC", "Timezone=America/Toronto" })
        {
            await using var zoned = Db.DataSource(options);
            foreach (var kind in new[] { DateTimeKind.Utc, DateTimeKind.Unspecified })
            {
                await using var command = zoned.CreateCommand("SELECT count(*) FROM ci.runs WHERE started_at >= $1");
                command.Parameters.Add(new() { Value = new DateTime(2026, 9, 14, 0, 0, 0, kind) });
                Console.WriteLine($"{options}, Kind={kind}: {await command.ExecuteScalarAsync()} runs since 2026-09-14 00:00");
            }
        }
        await using (var command = dataSource.CreateCommand("SELECT count(*) FROM ci.runs WHERE started_at >= $1"))
        {
            var toronto = new DateTimeOffset(2026, 9, 14, 0, 0, 0, TimeSpan.FromHours(-4));
            command.Parameters.Add(new() { Value = toronto });
            try
            {
                await command.ExecuteScalarAsync();
            }
            catch (ArgumentException e)
            {
                Console.WriteLine($"{e.GetType().Name}: {e.Message}");
            }
            command.Parameters[0].Value = toronto.ToUniversalTime();
            Console.WriteLine($"DateTimeOffset in UTC: {await command.ExecuteScalarAsync()} runs since 2026-09-14 00:00 in Toronto");
        }
```

```text
Timezone=UTC, Kind=Utc: 82 runs since 2026-09-14 00:00
Timezone=UTC, Kind=Unspecified: 82 runs since 2026-09-14 00:00
Timezone=America/Toronto, Kind=Utc: 82 runs since 2026-09-14 00:00
Timezone=America/Toronto, Kind=Unspecified: 59 runs since 2026-09-14 00:00
ArgumentException: Cannot write DateTimeOffset with Offset=-04:00:00 to PostgreSQL type 'timestamp with time zone', only offset 0 (UTC) is supported.  (Parameter 'value')
DateTimeOffset in UTC: 59 runs since 2026-09-14 00:00 in Toronto
```

- Le même `DateTime`, minuit le 14 septembre, compte 82 exécutions dans trois cas, et 59 quand il est `Unspecified` et que la session est à Toronto : minuit à Toronto est 04:00 UTC, et 23 exécutions ont commencé entre les deux. L'exercice 2 de la leçon 2 trouvait les mêmes 23 exécutions.
- La requête est correcte dans les quatre cas. Le compte dépend d'un `Kind` qui vient de l'endroit où le `DateTime` a été créé, et d'un réglage de session. Envoie des valeurs `Kind=Utc` aux colonnes `timestamptz`.
- Un [`DateTimeOffset`](https://learn.microsoft.com/dotnet/api/system.datetimeoffset) avec un décalage non nul est refusé avant tout envoi : `timestamptz` ne stocke pas de décalage (leçon 2), et Npgsql ne veut pas en supprimer un en silence. Convertis avec `ToUniversalTime()`.

En Java, [`OffsetDateTime`](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/time/OffsetDateTime.html) garde son décalage jusqu'au serveur, et le serveur compare des instants ([`L04.java`, lignes 80-87](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L80-L87)) :

```java
            // Un OffsetDateTime garde son décalage ; le serveur compare des instants
            try (PreparedStatement ps = connection.prepareStatement("SELECT count(*) FROM ci.runs WHERE started_at >= ?")) {
                ps.setObject(1, OffsetDateTime.of(2026, 9, 14, 0, 0, 0, 0, ZoneOffset.ofHours(-4)));
                try (ResultSet rs = ps.executeQuery()) {
                    rs.next();
                    System.out.println("runs since 2026-09-14 00:00 in Toronto: " + rs.getLong(1));
                }
            }
```

```text
runs since 2026-09-14 00:00 in Toronto: 59
```

En lecture, `reader.GetDateTime` renvoie un `DateTime` avec `Kind=Utc`, et `rs.getObject(2, OffsetDateTime.class)` un `OffsetDateTime` en UTC, quel que soit le fuseau de la session : les premières lignes des deux sorties ci-dessus. Seule une valeur mise en texte par le serveur, comme `rs.getString`, suit le `TimeZone` de la session.

### Types des paramètres

Un paramètre a un type, et PostgreSQL ne convertit pas une chaîne en nombre en silence ([`L04.cs`, lignes 96-108](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L96-L108), [`L04.java`, lignes 89-95](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L89-L95)) :

```csharp
        // Une valeur qui ne correspond pas au type de la colonne est une erreur de PostgreSQL, pas de Npgsql
        await using (var command = dataSource.CreateCommand("SELECT count(*) FROM ci.runs WHERE run_id = $1"))
        {
            command.Parameters.Add(new() { Value = "34852867099" });
            try
            {
                await command.ExecuteScalarAsync();
            }
            catch (PostgresException e)
            {
                Console.WriteLine($"{e.SqlState}: {e.MessageText}");
            }
        }
```

```text
42883: operator does not exist: bigint = text
```

```java
            // setString lie un varchar : PostgreSQL n'a pas d'opérateur bigint = varchar
            try (PreparedStatement ps = connection.prepareStatement("SELECT count(*) FROM ci.runs WHERE run_id = ?")) {
                ps.setString(1, "34852867099");
                ps.executeQuery();
            } catch (PSQLException e) {
                System.out.println(e.getSQLState() + ": " + e.getServerErrorMessage().getMessage());
            }
```

```text
42883: operator does not exist: bigint = character varying
```

Npgsql envoie une `string` comme `text`, pgjdbc envoie `setString` comme `varchar`, et aucun des deux types n'a d'opérateur `=` avec `bigint`. SQL Server convertirait la chaîne implicitement. La correction est le bon type .NET ou Java ; la propriété [`stringtype=unspecified`](https://jdbc.postgresql.org/documentation/use/) de pgjdbc envoie les chaînes sans type et laisse le serveur déduire le type, ce qui cache aussi les erreurs. L'erreur `42883` est `undefined_function` dans la [liste des codes d'erreur](https://www.postgresql.org/docs/18/errcodes-appendix.html) : un opérateur est une fonction.

## Pools

Ouvrir une connexion PostgreSQL démarre un **processus serveur**, le « un processus par connexion » de la leçon 1 : une connexion TCP, une authentification, un fork. Un pool garde les connexions ouvertes et les redistribue ([`L04.cs`, lignes 111-153](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L111-L153)) :

```csharp
    public static async Task Pool()
    {
        foreach (var pooling in new[] { true, false })
        {
            await using var dataSource = Db.DataSource($"Pooling={pooling}");
            var backends = new HashSet<int>();
            for (var i = 0; i < 20; i++)
            {
                await using var connection = await dataSource.OpenConnectionAsync();
                backends.Add(connection.ProcessID);
            }
            Console.WriteLine($"Pooling={pooling}: 20 opens, {backends.Count} server process(es)");
        }

        // Cinq connexions tenues en même temps sont cinq processus serveur
        await using (var dataSource = Db.DataSource("Application Name=learn-pool"))
        {
            var connections = new List<NpgsqlConnection>();
            for (var i = 0; i < 5; i++)
            {
                connections.Add(await dataSource.OpenConnectionAsync());
            }
            foreach (var connection in connections)
            {
                await connection.CloseAsync();
            }
            await using var command = dataSource.CreateCommand("""
                SELECT state, count(*) FROM pg_stat_activity
                WHERE application_name = 'learn-pool' GROUP BY state ORDER BY state
                """);
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                Console.WriteLine($"after closing: {reader.GetInt64(1)} {reader.GetString(0)}");
            }
        }
        await using (var dataSource = Db.DataSource())
        {
            await using var command = dataSource.CreateCommand(
                "SELECT count(*) FROM pg_stat_activity WHERE application_name = 'learn-pool'");
            Console.WriteLine($"after disposing the data source: {await command.ExecuteScalarAsync()}");
        }
    }
```

```text
Pooling=True: 20 opens, 1 server process(es)
Pooling=False: 20 opens, 20 server process(es)
after closing: 1 active
after closing: 4 idle
after disposing the data source: 0
```

- Avec le pool, 20 ouvertures et fermetures utilisent un seul processus serveur ; sans, 20.
- Cinq connexions tenues en même temps sont cinq processus. Fermées, elles restent ouvertes sur le serveur, `idle`, dans le pool. La seule session `active` est la connexion qui exécute la requête sur `pg_stat_activity` elle-même.
- Libérer la source de données ferme ses connexions.

Le pool de Npgsql est actif par défaut, par source de données, avec au plus 100 connexions (`Maximum Pool Size`) et un minimum de 0 ; les connexions inactives au-delà du minimum sont fermées après 300 secondes ([paramètres de la chaîne de connexion](https://www.npgsql.org/doc/connection-string-parameters.html)). SqlClient a les mêmes valeurs par défaut, 100 et 0.

pgjdbc n'a pas de pool à lui : chaque `DriverManager.getConnection` est un nouveau processus. HikariCP est le pool habituel ([`L04.java`, lignes 107-142](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L107-L142)) :

```java
    static void pool() throws SQLException {
        Set<Integer> backends = new HashSet<>();
        for (int i = 0; i < 20; i++) {
            try (Connection connection = DriverManager.getConnection(url())) {
                backends.add(backendPid(connection));
            }
        }
        System.out.println("DriverManager: 20 connections, " + backends.size() + " server process(es)");

        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(url().replace("learn-java", "learn-hikari"));
        config.setMaximumPoolSize(5);
        try (HikariDataSource pool = new HikariDataSource(config)) {
            backends.clear();
            for (int i = 0; i < 20; i++) {
                try (Connection connection = pool.getConnection()) {
                    backends.add(backendPid(connection));
                }
            }
            System.out.println("HikariCP: 20 connections, " + backends.size() + " server process(es)");
            // HikariCP ouvre des connexions en arrière-plan jusqu'à minimumIdle, qui vaut maximumPoolSize par défaut
            try (Connection connection = pool.getConnection()) {
                long deadline = System.currentTimeMillis() + 10_000;
                long sessions;
                do {
                    try (Statement statement = connection.createStatement();
                         ResultSet rs = statement.executeQuery(
                                 "SELECT count(*) FROM pg_stat_activity WHERE application_name = 'learn-hikari'")) {
                        rs.next();
                        sessions = rs.getLong(1);
                    }
                } while (sessions < 5 && System.currentTimeMillis() < deadline && sleep(100));

### Un pool rencontre max_connections

Le serveur a aussi une limite, [`max_connections`](https://www.postgresql.org/docs/18/runtime-config-connection.html#GUC-MAX-CONNECTIONS), 100 par défaut ([`L04.cs`, lignes 308-331](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L308-L331)) :

La taille maximale par défaut du pool de Npgsql est le nombre maximal de connexions par défaut du serveur. Une instance de l'application à pleine charge peut toutes les prendre ; deux instances avec les réglages par défaut peuvent en demander 200. Dimensionne les pools d'après la limite du serveur : la somme sur toutes les instances de l'application, plus les administrateurs, doit rester en dessous. Les connexions sont des processus coûteux, et quelques dizaines de connexions bien utilisées font généralement mieux que des centaines de connexions inactives.

## Instructions préparées

Une instruction préparée est analysée et planifiée une fois, puis exécutée avec de nouveaux paramètres. Les deux pilotes ne préparent sur le serveur qu'après quelques exécutions d'une instruction ([`L04.cs`, lignes 155-170](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L155-L170), [`L04.java`, lignes 154-171](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L154-L171)) :

Une instruction préparée appartient à une session, et une connexion de pool la garde d'une ouverture à l'autre : c'est pourquoi les pools comptent ici. La leçon 5 revient sur les plans génériques et personnalisés.

## Chargements en masse : COPY et lots

La leçon 1 chargeait des fichiers avec `COPY … FROM` un chemin **sur le serveur**. Depuis un programme, `COPY … FROM STDIN` envoie les lignes par la connexion. Npgsql les écrit dans le format binaire de PostgreSQL, typées ([`L04.cs`, lignes 172-208](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L172-L208)) :

```csharp
    static IEnumerable<string[]> PackageRefs() =>
        File.ReadLines("../ladybugdb/data/ga/package_refs.csv").Skip(1).Select(line => line.Split(','));

    public static async Task Copy()
    {
        await using var dataSource = Db.DataSource();
        await using var connection = await dataSource.OpenConnectionAsync();
        await using (var create = new NpgsqlCommand("""
            DROP TABLE IF EXISTS ga.package_refs_import;
            CREATE TABLE ga.package_refs_import (LIKE ga.package_refs INCLUDING ALL);
            """, connection))
        {
            await create.ExecuteNonQueryAsync();
        }

        // COPY ... FROM STDIN au format binaire : le client envoie les lignes, typées, en un seul flux
        await using (var writer = await connection.BeginBinaryImportAsync(
            "COPY ga.package_refs_import (project, package, version) FROM STDIN (FORMAT binary)"))
        {
            foreach (var fields in PackageRefs())
            {
                await writer.StartRowAsync();
                await writer.WriteAsync(fields[0], NpgsqlDbType.Text);
                await writer.WriteAsync(fields[1], NpgsqlDbType.Text);
                await writer.WriteAsync(fields[2], NpgsqlDbType.Text);
            }
            Console.WriteLine($"copied: {await writer.CompleteAsync()} rows");
        }

        await using var compare = new NpgsqlCommand("""
            SELECT (SELECT count(*) FROM (TABLE ga.package_refs EXCEPT TABLE ga.package_refs_import) AS d),
                   (SELECT count(*) FROM (TABLE ga.package_refs_import EXCEPT TABLE ga.package_refs) AS d)
            """, connection);
        await using var reader = await compare.ExecuteReaderAsync();
        await reader.ReadAsync();
        Console.WriteLine($"rows only in the server-side load: {reader.GetInt64(0)}, only in the client copy: {reader.GetInt64(1)}");
    }

## Clés générées

`RETURNING` (leçon 3) renvoie ce que le serveur a généré. L'API portable de JDBC pour cela est [`Statement.RETURN_GENERATED_KEYS`](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/Connection.html#prepareStatement(java.lang.String,int)) ([`L04.java`, lignes 199-241](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L199-L241)) :

```java
    static void generatedKeys() throws SQLException {
        try (Connection connection = DriverManager.getConnection(url())) {
            try (Statement statement = connection.createStatement()) {
                statement.execute("""
                        DROP TABLE IF EXISTS ci.notes;
                        CREATE TABLE ci.notes (
                            note_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
                            run_id  bigint NOT NULL REFERENCES ci.runs,
                            body    text NOT NULL,
                            created timestamptz NOT NULL DEFAULT '2026-09-15 00:00:00+00'
                        );
                        """);
            }
            // RETURN_GENERATED_KEYS : le pilote ajoute RETURNING * à l'INSERT
            try (PreparedStatement ps = connection.prepareStatement(
                    "INSERT INTO ci.notes (run_id, body) VALUES (?, ?)", Statement.RETURN_GENERATED_KEYS)) {
                ps.setLong(1, 34852867099L);
                ps.setString(2, "first deployment of the day");
                ps.executeUpdate();
                try (ResultSet keys = ps.getGeneratedKeys()) {
                    keys.next();
                    int columns = keys.getMetaData().getColumnCount();
                    StringBuilder line = new StringBuilder("generated keys:");
                    for (int c = 1; c <= columns; c++) {
                        line.append(' ').append(keys.getMetaData().getColumnName(c)).append('=').append(keys.getString(c));
                    }
                    System.out.println(line);
                }
            }
            // Nommer les colonnes ne demande que RETURNING note_id
            try (PreparedStatement ps = connection.prepareStatement(
                    "INSERT INTO ci.notes (run_id, body) VALUES (?, ?)", new String[] {"note_id"})) {
                ps.setLong(1, 34852867099L);
                ps.setString(2, "second note");
                ps.executeUpdate();
                try (ResultSet keys = ps.getGeneratedKeys()) {
                    keys.next();
                    System.out.println("generated keys: " + keys.getMetaData().getColumnCount() + " column, note_id="
                            + keys.getLong("note_id"));
                }
            }
        }
    }

{
    public DbSet<CachedIconicChord> IconicChords => Set<CachedIconicChord>();

    protected override void OnConfiguring(DbContextOptionsBuilder options) => options.UseNpgsql(Db.ConnectionString);

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasDefaultSchema(withConverters ? "ef_ga" : "ef_native");
        modelBuilder.Entity<CachedIconicChord>(entity =>
        {
            entity.HasKey(e => e.Id);
            entity.HasIndex(e => e.Name);
            if (!withConverters)
            {
                return;
            }
            entity.Property(e => e.PitchClasses).HasConversion(
                v => string.Join(',', v),
                v => v.Split(',', StringSplitOptions.RemoveEmptyEntries).Select(int.Parse).ToList()
            );
            entity.Property(e => e.GuitarVoicing).HasConversion(
                v => v != null ? string.Join(',', v) : null,

                    ? v.Split(',', StringSplitOptions.RemoveEmptyEntries).Select(int.Parse).ToList()
                    : null
            );
            entity.Property(e => e.AlternateNames).HasConversion(
                v => string.Join('|', v),
                v => v.Split('|', StringSplitOptions.RemoveEmptyEntries).ToList()
            );
        });

C'est un constat sur le code de GA, pas sur PostgreSQL, et le tableau natif n'a pas le problème.

## Erreurs

Une erreur du serveur arrive comme [`PostgresException`](https://www.npgsql.org/doc/api/Npgsql.PostgresException.html) dans Npgsql, et `PSQLException` dans pgjdbc, avec le `SqlState` à cinq caractères de l'[annexe des codes d'erreur](https://www.postgresql.org/docs/18/errcodes-appendix.html). Teste le code, pas le message : `23505` est `unique_violation` dans tous les langages, alors que le message suit `lc_messages`. Npgsql définit aussi des constantes comme `PostgresErrorCodes.UniqueViolation`.

Le `DETAIL` d'une erreur peut contenir des données, comme le « Failing row contains … » de la leçon 2. Npgsql le masque sauf si la chaîne de connexion règle `Include Error Detail=true` ; l'exercice 1 montre les deux.

## Sur Aurora

*À vérifier : rien dans cette section n'a été exécuté sur AWS.* Npgsql et pgjdbc se connectent à Aurora PostgreSQL comme à n'importe quel serveur PostgreSQL. Ce qui change est autour de la connexion.

**TLS est exigé par défaut.** La [page de sécurité d'Aurora PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraPostgreSQL.Security.html) donne la valeur par défaut de `rds.force_ssl` comme 1 (activé) pour Aurora PostgreSQL 17 et plus, et 0 pour 16 et avant ; une connexion sans TLS est refusée avec `no pg_hba.conf entry for host …, SSL off`. Le conteneur local a `ssl` désactivé. Les deux pilotes utilisent `prefer` par défaut, qui utilise TLS quand le serveur le propose mais ne vérifie pas le certificat. Contre Aurora, utilise `SSL Mode=VerifyFull` dans Npgsql et `sslmode=verify-full` dans pgjdbc, avec le paquet d'autorités de certification RDS comme racine de confiance.

**Mots de passe ou jetons IAM.** Avec l'[authentification IAM à la base](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/UsingWithRDS.IAMDBAuth.html), le mot de passe est un jeton généré par le SDK AWS à partir d'identifiants IAM. AWS lui donne « a lifetime of 15 minutes », précise qu'il « doesn't affect the session after it is established », et que sa taille « is generally about 1 KB but can be larger ». Un pool ouvre de nouvelles connexions toute la journée, donc le jeton doit être renouvelé :

- En .NET, [`NpgsqlDataSourceBuilder.UsePeriodicPasswordProvider`](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/NpgsqlDataSourceBuilder.cs#L344-L371) appelle une fonction sur minuterie, « the recommended way to fetch a rotating access token » selon son commentaire de documentation ; la fonction appellerait le `RDSAuthTokenGenerator` du SDK AWS pour .NET.
- En Java, AWS documente le plugin d'authentification IAM de l'[AWS Advanced JDBC Wrapper](https://github.com/aws/aws-advanced-jdbc-wrapper), qui enveloppe pgjdbc.

**max_connections dépend de l'instance.** Sa valeur par défaut sur Aurora PostgreSQL est `LEAST({DBInstanceClassMemory/9531392},5000)`, d'après [performances et mise à l'échelle d'Aurora PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraPostgreSQL.Managing.html), qui recommande aussi de garder « at least 3 more connections to support AWS automation ». Le `53300` de la section sur les pools arrive à ce nombre, quel qu'il soit ; l'arithmétique des tailles de pools est la même.

**RDS Proxy et l'épinglage.** [RDS Proxy](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-proxy.html) partage les connexions à la base entre les connexions clientes aux limites des transactions. Une connexion cliente dont l'état de session a changé est **épinglée** à sa connexion à la base jusqu'à ce qu'elle se déconnecte. La [liste des conditions d'épinglage pour PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-proxy-pinning.html#rds-proxy-pinning.postgres) d'AWS croise les pilotes de cette leçon à trois endroits :

- « Using `SET` commands » épingle. Un réglage de session comme le fuseau horaire a sa place dans la chaîne de connexion (`Timezone`, ou le fuseau de la JVM pour pgjdbc, envoyé au démarrage), ou dans la requête d'initialisation du proxy. Que RDS Proxy épingle sur des paramètres envoyés dans le message de démarrage est *à vérifier*.
- « Using `PREPARE`, `DISCARD`, `DEALLOCATE`, or `EXECUTE` commands to manage prepared statements » épingle. La préparation automatique des pilotes utilise les messages du protocole, pas ces commandes SQL ; la page ne dit pas si cela épingle, donc c'est *à vérifier*.
- « If you use connection pooling libraries with `DISCARD ALL` query configured as a reset query, RDS Proxy pins your client connection on release. » Npgsql réinitialise une connexion de pool avec `DISCARD ALL` quand elle retourne au pool, sauf si elle a des instructions préparées ([`NpgsqlConnector.cs`, lignes 2752-2766](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/Internal/NpgsqlConnector.cs#L2752-L2766)). `No Reset On Close=true` désactive la réinitialisation, « at the cost of leaking state ». Derrière RDS Proxy, un pool dans l'application et un pool dans le proxy sont deux couches qui font le même travail.

**Writer et readers.** La leçon 3 a décrit le cluster endpoint et le reader endpoint. Un programme peut tenir une source de données par endpoint, ou donner les deux hôtes à une seule source de données et laisser le pilote choisir selon le rôle : l'exercice 3 l'essaie sur le serveur local. Pour un basculement rapide en Java, AWS maintient l'AWS Advanced JDBC Wrapper, qui suit la topologie du cluster au lieu de s'appuyer sur le DNS.

## À retenir

- Une `NpgsqlDataSource` par base, gardée pendant toute la vie de l'application ; en Java, un pool HikariCP autour de pgjdbc.
- Utilise les vrais types des paramètres. Une chaîne comparée à un `bigint` est l'erreur `42883`, pas une conversion.
- Envoie les valeurs `DateTime` avec `Kind=Utc` aux `timestamptz` ; convertis les `DateTimeOffset` en UTC. pgjdbc règle le fuseau horaire de la session d'après la JVM.
- `Maximum Pool Size` vaut 100 par défaut et `max_connections` 100 : dimensionne les pools d'après la limite du serveur.
- Les deux pilotes préparent les instructions sur le serveur après 5 exécutions, Npgsql seulement quand `Max Auto Prepare` est réglé.
- `COPY FROM STDIN` et les lots chargent les lignes en un aller-retour ; un `INSERT` par ligne paie un aller-retour par ligne.
- Le fournisseur EF Core fait correspondre les tableaux nativement ; des convertisseurs de valeurs écrits pour SQLite perdent de l'information et cachent les problèmes de `DateTime.Kind`.
- Sur Aurora : TLS exigé à partir de la version 17, jetons IAM valides 15 minutes, `max_connections` d'après la mémoire de l'instance, et une réinitialisation `DISCARD ALL` qui épingle les connexions de RDS Proxy.

    public static async Task ExerciseBatch()
    {
        await using var dataSource = Db.DataSource();

                command.Parameters.Add(new() { Value = field });

        }
        try

        }
        catch (PostgresException e)
        {
            Console.WriteLine($"{e.SqlState}: {e.MessageText}");
            Console.WriteLine(e.Detail);
        }

```java
    static void exerciseBatch() throws Exception {
        try (Connection connection = DriverManager.getConnection(url() + "&reWriteBatchedInserts=true")) {
            try (Statement statement = connection.createStatement()) {
                statement.execute("""
                        DROP TABLE IF EXISTS ga.package_refs_batch;
                        CREATE TABLE ga.package_refs_batch (LIKE ga.package_refs INCLUDING ALL);
                        """);
            }
            List<String> lines = Files.readAllLines(Path.of("../ladybugdb/data/ga/package_refs.csv"));
            List<String> rows = new java.util.ArrayList<>(lines.subList(1, lines.size()));
            rows.add(rows.get(0));
            connection.setAutoCommit(false);
            try (PreparedStatement ps = connection.prepareStatement("INSERT INTO ga.package_refs_batch VALUES (?, ?, ?)")) {
                for (String row : rows) {
                    String[] fields = row.split(",");
                    ps.setString(1, fields[0]);
                    ps.setString(2, fields[1]);
                    ps.setString(3, fields[2]);
                    ps.addBatch();
                }
                ps.executeBatch();
                connection.commit();
            } catch (BatchUpdateException e) {
                connection.rollback();
                SQLException cause = e.getNextException();
                System.out.println(cause.getSQLState() + ": " + ((PSQLException) cause).getServerErrorMessage().getMessage());
            }
            connection.setAutoCommit(true);
            try (Statement statement = connection.createStatement();
                 ResultSet rs = statement.executeQuery("SELECT count(*) FROM ga.package_refs_batch")) {
                rs.next();
                System.out.println("rows in the table: " + rs.getLong(1));
            }
        }
    }
```

```text
23505: duplicate key value violates unique constraint "package_refs_batch_pkey"
rows in the table: 0
```

- **Zéro ligne dans les deux.** Un `NpgsqlBatch` s'exécute dans une transaction implicite : l'échec de la 479e instruction annule les 478 qui la précèdent. En Java, `setAutoCommit(false)` et `rollback()` font la même chose explicitement ; en autocommit, chaque instruction du lot validerait seule.
- `reWriteBatchedInserts=true` laisse pgjdbc réécrire le lot en instructions `INSERT … VALUES (…), (…)` à plusieurs lignes. L'erreur arrive comme une `BatchUpdateException`, dont `getNextException()` porte l'erreur du serveur.
- Npgsql masque le détail. Avec `Include Error Detail=true` dans `PG_CONNECTION`, la deuxième ligne devient `Key (project, package)=(AllProjects.AppHost/AllProjects.AppHost.csproj, Aspire.Dashboard.Sdk.win-x64) already exists.`, ce que j'ai exécuté le 2026-09-15 mais que `check.sh` ne compare pas.

3. Ton application tournera sur un cluster Aurora avec un writer et un reader endpoint. Contre le serveur local, demande à chaque pilote une connexion à un **standby**, puis à un standby s'il y en a un et au primaire sinon. Que font les pilotes, et de quoi une chaîne de connexion a-t-elle besoin pour cela ?

<details>
<summary>Solution</summary>

[`L04.cs`, lignes 333-361](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L333-L361) :

```csharp
    public static async Task Target()
    {
        // Dans une chaîne de connexion, Target Session Attributes exige plusieurs hôtes, comme les endpoints writer et reader d'Aurora
        try
        {
            Db.DataSource("Target Session Attributes=standby");
        }
        catch (NotSupportedException e)
        {
            Console.WriteLine($"one host: {e.GetType().Name}: {e.Message}");
        }

        // Une source de données multi-hôtes vérifie le rôle de chaque serveur avant de donner une connexion ; le serveur local est un primaire
        await using var multiHost = new NpgsqlDataSourceBuilder(Db.ConnectionString).BuildMultiHost();
        foreach (var target in new[] { TargetSessionAttributes.ReadWrite, TargetSessionAttributes.PreferStandby, TargetSessionAttributes.Standby })
        {
            var dataSource = multiHost.WithTargetSession(target);
            try
            {
                await using var connection = await dataSource.OpenConnectionAsync();
                await using var command = new NpgsqlCommand("SELECT pg_is_in_recovery()", connection);
                Console.WriteLine($"{target}: connected, pg_is_in_recovery() = {await command.ExecuteScalarAsync()}");
            }
            catch (NpgsqlException e)
            {
                Console.WriteLine($"{target}: {e.GetType().Name}: {e.Message}");
            }
        }
    }
```

ReadWrite: connected, pg_is_in_recovery() = False
PreferStandby: connected, pg_is_in_recovery() = False

```

[`L04.java`, lignes 279-292](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L279-L292) :

```java
    static void target() {
        // targetServerType : avant de donner une connexion, le pilote vérifie le rôle du serveur, comme il le ferait pour chaque
        // hôte d'un cluster Aurora ; le serveur local est un primaire
        for (String target : List.of("primary", "preferSecondary", "secondary")) {
            try (Connection connection = DriverManager.getConnection(url() + "&targetServerType=" + target);
                 Statement statement = connection.createStatement();
                 ResultSet rs = statement.executeQuery("SELECT pg_is_in_recovery()")) {
                rs.next();
                System.out.println(target + ": connected, pg_is_in_recovery() = " + rs.getBoolean(1));
            } catch (SQLException e) {
                System.out.println(target + ": " + e.getSQLState() + ": " + e.getMessage());
            }
        }
    }
```

```text
primary: connected, pg_is_in_recovery() = false
preferSecondary: connected, pg_is_in_recovery() = false
secondary: 08001: Could not find a server with specified targetServerType: secondary
```

- Npgsql refuse `Target Session Attributes` avec un seul hôte dans une chaîne de connexion, avant de se connecter ([`NpgsqlConnectionStringBuilder.cs`, lignes 1508-1514](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/NpgsqlConnectionStringBuilder.cs#L1508-L1514)). Plusieurs hôtes vont dans `Host`, comme `Host=writer-endpoint,reader-endpoint`. `BuildMultiHost()` construit une source de données sur eux, et `WithTargetSession` en dérive une source de données pour un rôle. D'après [plusieurs hôtes et basculement](https://www.npgsql.org/doc/failover-and-load-balancing.html), Npgsql « detects whether a server is a primary or a standby by occasionally querying `pg_is_in_recovery()` », et vérifie de nouveau toutes les `Host Recheck Seconds`, 10 par défaut.
- pgjdbc accepte un seul hôte et vérifie le rôle du serveur à la connexion : `targetServerType=secondary` ne trouve pas de standby, SQLSTATE `08001`. Plusieurs hôtes vont dans l'URL, `jdbc:postgresql://writer-endpoint,reader-endpoint/learn`.
- Les deux ne trouvent pas de standby sur le primaire local, et les deux se replient sur lui avec `prefer-standby` et `preferSecondary`.

Sur Aurora, le reader endpoint pointe déjà vers les réplicas, et une source de données distincte par endpoint est la conception la plus simple. La sélection par rôle sert quand les deux endpoints sont dans une seule chaîne de connexion, et pendant un basculement, quand le reader endpoint « might direct connections to the new primary DB instance », selon la [page des endpoints](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Overview.Endpoints.html). Qu'une Aurora Replica réponde vrai à `pg_is_in_recovery()`, comme un standby PostgreSQL, est *à vérifier*.

</details>
