## Qué CLI

`algo` y `fts` son [extensiones](https://docs.ladybugdb.com/extensions/), como `json` en la lección 2: `INSTALL` las descarga una vez, `LOAD` las carga en cada sesión. Con la CLI 0.20.4, la CI imprime esto en el runner de Linux:

```text
Extension: algo installed from the repo: https://extension.ladybugdb.com/.
Error: IO exception: Failed to load library: /home/runner/.lbdb/extension/0.20.0/linux_amd64/algo/libalgo.lbug_extension which is needed by extension: algo.
Error: libnetworkit.so: cannot open shared object file: No such file or directory.
Extension: fts installed from the repo: https://extension.ladybugdb.com/.
Extension: fts has been loaded.
```

Las CLI 0.20.x descargan las extensiones compiladas para 0.20.0, y `algo` necesita una biblioteca que no se publica con ella: `libnetworkit.dylib` en el runner de macOS, una DLL que el error no nombra en Windows. El problema está [abierto en el tracker de LadybugDB](https://github.com/LadybugDB/ladybug/issues/857). `fts` se carga en los tres runners, pero en mi máquina Windows la CLI 0.20.4 se detiene en el primer `CREATE_FTS_INDEX`, sin mensaje, con el código de salida `0xC0000409`. Dos issues cerrados describen la misma familia de problemas: [extensiones de otra versión](https://github.com/LadybugDB/ladybug/issues/903) y [dependencias de Windows de `fts` que faltan](https://github.com/LadybugDB/ladybug/issues/942).

La CLI 0.19.1 descarga las extensiones compiladas para 0.19.0, y ambas se cargan y funcionan en Windows, Linux y macOS. El curso la instala junto a la 0.20.4 con otro nombre, `lbug19`:

## Grafos proyectados

Los algoritmos no se ejecutan sobre tablas sino sobre un *grafo proyectado*: un nombre para un conjunto de tablas de nodos y de relaciones, que la conexión conserva hasta cerrarse ([líneas 8-15](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L8-L15)):

```cypher
CREATE NODE TABLE Project(path STRING PRIMARY KEY, name STRING, language STRING, sdk STRING, frameworks STRING, in_solution BOOLEAN);
CREATE REL TABLE REFERENCES(FROM Project TO Project);
COPY Project FROM 'data/ga/projects.csv' (HEADER = true);
COPY REFERENCES FROM 'data/ga/project_refs.csv' (HEADER = true, IGNORE_ERRORS = true);

CALL project_graph('Deps', ['Project'], ['REFERENCES']);
CALL show_projected_graphs() RETURN *;
```

```text
┌────────┬────────┐
│ name   │ type   │
│ STRING │ STRING │
├────────┼────────┤
│ Deps   │ NATIVE │
└────────┴────────┘
```

Los mismos 111 proyectos y 265 referencias que en la lección 5; la 266.ª apunta a un proyecto JavaScript, que no está en `projects.csv`, y va a las advertencias. No se copia nada: la [documentación](https://docs.ladybugdb.com/extensions/algo/) dice que el algoritmo lee las tablas del disco cuando se ejecuta. Cada algoritmo es una función de tabla, llamada con `CALL`, que devuelve una fila por nodo.

## Componentes: ciclos e islas

Una compilación solo puede ordenar los proyectos si ninguna referencia da la vuelta en círculo. Las *componentes fuertemente conexas* son los grupos de nodos que se alcanzan todos entre sí ([líneas 18-21](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L18-L21)):

```cypher
CALL strongly_connected_components('Deps')
WITH group_id, count(*) AS projects
RETURN projects, count(*) AS components
ORDER BY projects DESC;
```

```text
┌──────────┬────────────┐
│ projects │ components │
│ INT64    │ INT64      │
├──────────┼────────────┤
│ 1        │ 111        │
└──────────┴────────────┘
```

111 componentes de un proyecto: ningún ciclo, como exige MSBuild. Las *componentes débilmente conexas* ignoran la dirección: dos proyectos están en la misma cuando una cadena de referencias los conecta, en cualquier dirección ([líneas 24-27](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L24-L27)):

```text
┌──────────┬────────────┐
│ projects │ components │
│ INT64    │ INT64      │
├──────────┼────────────┤
│ 92       │ 1          │
│ 1        │ 19         │
└──────────┴────────────┘
```

Un continente de 92 proyectos, y 19 islas. Los valores de `group_id` dependen de los offsets internos de los nodos, así que las consultas agrupan por ellos pero nunca los imprimen. ¿Qué proyectos son las islas ([líneas 30-35](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L30-L35))?

```cypher
CALL weakly_connected_components('Deps')
WITH group_id, collect(node) AS members
WHERE size(members) = 1
UNWIND members AS p
RETURN p.path AS path, p.in_solution AS in_solution
ORDER BY p.path;
```

Que haya herramientas, demos y experimentos aislados es de esperar. `ReactApp1.Server` tiene una referencia, al proyecto JavaScript que el `COPY` omitió. Si no se usan o se referencian de otra forma está *por verificar* en ga. El alias `p.path AS path` importa: sin él, la cabecera CSV de la columna es `STRUCT_EXTRACT(p,path)`.

## PageRank

Un proyecto es importante cuando lo referencian proyectos importantes ([líneas 38-42](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L38-L42)):

```cypher
CALL page_rank('Deps')
WITH node, rank
RETURN node.name, round(rank, 4) AS rank, COUNT { MATCH (:Project)-[:REFERENCES]->(node) } AS referenced_by
ORDER BY rank DESC, node.name
LIMIT 6;
```

```text
┌────────────────────┬──────────┬───────────────┐
│ node.name          │ rank     │ referenced_by │
│ STRING             │ DOUBLE   │ INT64         │
├────────────────────┼──────────┼───────────────┤
│ GA.Domain.Core     │ 0.047700 │ 57            │
│ GA.Core            │ 0.044100 │ 32            │
│ GA.Business.Config │ 0.030600 │ 16            │
│ GA.Domain.Services │ 0.024300 │ 48            │
│ GA.Business.DSL    │ 0.011800 │ 14            │
│ GA.Business.ML     │ 0.010900 │ 21            │
└────────────────────┴──────────┴───────────────┘
```

La clasificación no es el número de referencias: `GA.Core`, referenciado 32 veces, queda por encima de `GA.Domain.Services`, referenciado 48 veces. El ejercicio 1 averigua por qué. [`page_rank`](https://docs.ladybugdb.com/extensions/algo/pagerank/) acepta argumentos opcionales, `dampingFactor := 0.85` y `maxIterations := 20` por defecto. El rango se redondea antes de ordenar: el `DOUBLE` completo podría diferir en sus últimos dígitos de una máquina a otra, y la salida CSV se compara en tres.

## Louvain, y un resultado que cambia

[Louvain](https://docs.ladybugdb.com/extensions/algo/louvain/) agrupa los nodos en comunidades, más conectadas por dentro que con el resto, ignorando la dirección ([líneas 56-58](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L56-L58)):

```cypher
CALL louvain('Deps')
WITH louvain_id, count(*) AS projects
RETURN count(*) AS groups, sum(CASE WHEN louvain_id = -1 THEN projects ELSE 0 END) AS without_community;
```

```text
┌────────┬───────────────────┐
│ groups │ without_community │
│ INT64  │ INT128            │
├────────┼───────────────────┤
│ 6      │ 19                │
└────────┴───────────────────┘
```

Cinco comunidades, y las 19 islas con `louvain_id` -1. La consulta solo imprime eso, porque los tamaños de las comunidades cambian de una ejecución de la CLI a la siguiente: `[27,20,17,14,14]` en un proceso, `[25,20,18,18,11]` en los dos siguientes, en mi máquina, incluso después de `CALL threads = 1`. Dentro de un proceso, tres llamadas dieron los mismos tamaños. Un resultado que cambia no puede ir en una salida esperada; para publicar comunidades, ejecuta Louvain una vez, guarda `louvain_id` en una propiedad y consulta la propiedad.

`sum` de un `INT64` devuelve un `INT128`, visible en la cabecera de la salida box.

## Proyecciones filtradas, y una que no funciona

Sin los proyectos de pruebas: la documentación de algo describe una proyección con un predicado por tabla, `n` para los nodos y `r` para las relaciones ([líneas 64-69](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L64-L69)):

```cypher
CALL project_graph('NoTestsFiltered', {'Project': 'NOT n.path STARTS WITH "Tests/"'}, ['REFERENCES']);
CALL page_rank('NoTestsFiltered')
WITH node, rank
RETURN node.name, round(rank, 4) AS rank
ORDER BY rank DESC, node.name
LIMIT 3;
```

```text
┌────────────────────┬──────────┐
│ node.name          │ rank     │
│ STRING             │ DOUBLE   │
├────────────────────┼──────────┤
│ GA.Domain.Core     │ 0.047700 │
│ GA.Core            │ 0.044500 │
│ GA.Business.Config │ 0.031000 │
└────────────────────┴──────────┘
```

Los 17 proyectos de pruebas referencian las bibliotecas, pero aportan poco rango: una sola referencia apunta a un proyecto de pruebas. El motor tiene otra función, `project_graph_cypher`, que define la proyección con una consulta Cypher, y que la documentación no menciona. Crea el grafo, pero los algoritmos lo rechazan ([líneas 61-62](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L61-L62)):

```cypher
CALL project_graph_cypher('NoTests', 'MATCH (a:Project)-[r:REFERENCES]->(b:Project) WHERE NOT a.path STARTS WITH \'Tests/\' RETURN a, r, b');
CALL page_rank('NoTests') RETURN count(*);
```

```text
Error: Binder exception: AA
```

`AA` es el mensaje entero: [`gds.cpp`, línea 72](https://github.com/LadybugDB/ladybug/blob/v0.19.1/src/function/gds/gds.cpp#L72), lo lanza cuando un algoritmo enlaza un grafo proyectado cuyo tipo no es `NATIVE`, en la 0.19.1 y todavía en la 0.20.4; las componentes débilmente conexas fallan de la misma forma. `show_projected_graphs()` lista `NoTests` con el tipo `CYPHER`; `drop_projected_graph` elimina ambos.

## Búsqueda de texto completo: índices

La segunda extensión. Las páginas del sitio y los commits de la lección 4, y cuatro índices ([líneas 75-84](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L75-L84)):

```cypher
CREATE NODE TABLE Page(url STRING PRIMARY KEY, locale STRING, course STRING, title STRING, lines INT64);
COPY Page FROM 'data/pages.csv' (HEADER = true);
CREATE NODE TABLE Commit(sha STRING PRIMARY KEY, committed_at TIMESTAMP, subject STRING);
COPY Commit FROM 'data/commits.csv' (HEADER = true, QUOTE = '"');

CALL CREATE_FTS_INDEX('Page', 'titles', ['title']);
CALL CREATE_FTS_INDEX('Page', 'titles_exact', ['title'], stemmer := 'none');
CALL CREATE_FTS_INDEX('Page', 'titles_fr', ['title'], stemmer := 'french');
CALL CREATE_FTS_INDEX('Commit', 'subjects', ['subject']);
CALL show_indexes() RETURN table_name, index_name, index_type, index_definition;
```

```text
┌────────────┬──────────────┬────────────┬─────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ table_name │ index_name   │ index_type │ index_definition                                                                                        │
│ STRING     │ STRING       │ STRING     │ STRING                                                                                                  │
├────────────┼──────────────┼────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Page       │ titles       │ FTS        │ CALL CREATE_FTS_INDEX('Page', 'titles', ['title'], stemmer := 'english', stopWords := 'default');       │
│ Page       │ titles_exact │ FTS        │ CALL CREATE_FTS_INDEX('Page', 'titles_exact', ['title'], stemmer := 'none', stopWords := 'default');    │
│ Page       │ titles_fr    │ FTS        │ CALL CREATE_FTS_INDEX('Page', 'titles_fr', ['title'], stemmer := 'french', stopWords := 'default');     │
│ Commit     │ subjects     │ FTS        │ CALL CREATE_FTS_INDEX('Commit', 'subjects', ['subject'], stemmer := 'english', stopWords := 'default'); │
│ Project    │ _PK          │ HASH       │                                                                                                         │
│ Page       │ _PK          │ HASH       │                                                                                                         │
│ Commit     │ _PK          │ HASH       │                                                                                                         │
└────────────┴──────────────┴────────────┴─────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

`show_indexes()` reescribe cada índice como la llamada que lo crea, con los valores predeterminados rellenados: el stemmer inglés y las stop words predeterminadas. Cada clave primaria tiene su índice hash. Un índice FTS trabaja sobre las propiedades `STRING` de una tabla de nodos, varias a la vez si las enumeras; una tabla puede tener varios índices, con nombres distintos.

## Consultas, stemmers y stop words

`QUERY_FTS_INDEX` devuelve los nodos que coinciden y su puntuación [BM25](https://en.wikipedia.org/wiki/Okapi_BM25) ([líneas 87-92](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L87-L92)):

```cypher
CALL QUERY_FTS_INDEX('Page', 'titles', 'query')
RETURN node.url, node.title, round(score, 4) AS score
ORDER BY score DESC, node.url;
CALL QUERY_FTS_INDEX('Page', 'titles_exact', 'query') RETURN count(*) AS pages;
CALL QUERY_FTS_INDEX('Page', 'titles_exact', 'queries') RETURN count(*) AS pages;
```

```text
┌───────────────────────────┬──────────────────┬──────────┐
│ node.url                  │ node.title       │ score    │
│ STRING                    │ STRING           │ DOUBLE   │
├───────────────────────────┼──────────────────┼──────────┤
│ /duckdb/01-first-queries/ │ 1. First queries │ 3.244500 │
└───────────────────────────┴──────────────────┴──────────┘
```

El stemmer reduce `query` y `queries` a la misma raíz, en el índice y en la búsqueda. Sin stemmer, `query` encuentra 0 páginas y `queries` 1. El título francés de esa página, `1. Premières requêtes`, no tiene ninguna de las dos palabras.

El idioma del stemmer cambia las raíces ([líneas 95-100](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L95-L100)):

```cypher
CALL QUERY_FTS_INDEX('Page', 'titles', 'persistant')
RETURN node.url, node.title
ORDER BY node.url;
CALL QUERY_FTS_INDEX('Page', 'titles_fr', 'persistant')
RETURN node.url, node.title
ORDER BY node.url;
```

```text
┌────────────────────────────┬──────────────────────────────────────────────┐
│ node.url                   │ node.title                                   │
│ STRING                     │ STRING                                       │
├────────────────────────────┼──────────────────────────────────────────────┤
│ /duckdb/08-persistence/    │ 8. Persistence, transactions and concurrency │
│ /fr/duckdb/08-persistence/ │ 8. Persistance, transactions et concurrence  │
└────────────────────────────┴──────────────────────────────────────────────┘
┌────────────────────────────┬─────────────────────────────────────────────┐
│ node.url                   │ node.title                                  │
│ STRING                     │ STRING                                      │
├────────────────────────────┼─────────────────────────────────────────────┤
│ /fr/duckdb/08-persistence/ │ 8. Persistance, transactions et concurrence │
└────────────────────────────┴─────────────────────────────────────────────┘
```

El stemmer inglés lleva *persistant*, *Persistence* y *Persistance* a la misma raíz; el francés deja *Persistence* aparte. Ninguno encuentra el español *Persistencia*. Un sitio en tres idiomas necesitaría un índice por idioma, sobre una propiedad por idioma, o un `WHERE node.locale = …` después de la búsqueda.

Luego mayúsculas, acentos y stop words ([líneas 103-107](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L103-L107)):

```cypher
CALL QUERY_FTS_INDEX('Page', 'titles', 'DONNÉES') RETURN count(*) AS pages;
CALL QUERY_FTS_INDEX('Page', 'titles', 'donnees') RETURN count(*) AS pages;
CALL QUERY_FTS_INDEX('Page', 'titles', 'the') RETURN count(*) AS pages;
CALL QUERY_FTS_INDEX('Page', 'titles_fr', 'de') RETURN count(*) AS pages;
```

2, 0, 0 y 32 páginas. `DONNÉES` encuentra *Données imbriquées* y *Visualisation de données*: las mayúsculas no importan. `donnees` no encuentra nada: los acentos no se normalizan. `the` es una stop word, excluida del índice. Pero las stop words predeterminadas son inglesas sea cual sea el stemmer: `de` se indexa en el índice francés, y 32 títulos la tienen. `CREATE_FTS_INDEX` acepta `stopWords :=` con el nombre de una tabla de nodos, o de un archivo CSV o Parquet, de una columna de palabras.

## Cualquier palabra, todas las palabras, y un índice que sigue a la tabla

Por defecto, una búsqueda con dos palabras devuelve los nodos que tienen *cualquiera* de ellas; `conjunctive := true` las exige todas ([líneas 110-114](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L110-L114)):

```cypher
CALL QUERY_FTS_INDEX('Commit', 'subjects', 'lesson exercises')
RETURN count(*) AS any_word;
CALL QUERY_FTS_INDEX('Commit', 'subjects', 'lesson exercises', conjunctive := true)
RETURN substring(node.sha, 1, 7) AS sha, node.subject, round(score, 4) AS score
ORDER BY score DESC, sha;
```

## Una búsqueda dentro de una consulta de grafo

El nodo que devuelve una búsqueda es un nodo como cualquier otro: un patrón puede continuar desde él. Los archivos modificados con más frecuencia por los commits sobre ejercicios ([líneas 123-132](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L123-L132)):

```cypher
CREATE NODE TABLE File(path STRING PRIMARY KEY);
CREATE REL TABLE CHANGED(FROM Commit TO File);
COPY File FROM (LOAD FROM 'data/changes.csv' (HEADER = true) RETURN DISTINCT file);
COPY CHANGED FROM 'data/changes.csv' (HEADER = true);
CALL QUERY_FTS_INDEX('Commit', 'subjects', 'exercises')
WITH node AS c
MATCH (c)-[:CHANGED]->(f:File)
RETURN f.path, count(*) AS commits
ORDER BY commits DESC, f.path
LIMIT 5;
```

```text
┌────────────────────────────────────────┬─────────┐
│ f.path                                 │ commits │
│ STRING                                 │ INT64   │
├────────────────────────────────────────┼─────────┤
│ code/duckdb/check.sh                   │ 2       │
│ .github/workflows/gha-02-exercises.yml │ 1       │
│ .github/workflows/gha-04-exercises.yml │ 1       │
│ .github/workflows/gha-05-exercises.yml │ 1       │
│ .github/workflows/gha-09-exercises.yml │ 1       │
└────────────────────────────────────────┴─────────┘
```

En SQL Server, la misma consulta combina `CONTAINSTABLE` con las tablas de commits y de archivos. `CALL … WITH node AS c` es aquí el join.

Para terminar, `DROP_FTS_INDEX` ([líneas 134-135](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-algorithms.cypher#L134-L135)):

```text
┌───────────────────────────────────────────┐
│ result                                    │
│ STRING                                    │
├───────────────────────────────────────────┤
│ Table 3_titles_fr_terms has been dropped. │
└───────────────────────────────────────────┘
Error: Binder exception: Table Page doesn't have an index with name titles_fr.
```

El mensaje muestra cómo se almacena el índice: en tablas internas cuyo nombre lleva el ID de la tabla y el índice, aquí `3_titles_fr_terms`, y que se eliminan con él.

## Puntos clave

- `algo` y `fts` son extensiones: `INSTALL` una vez, `LOAD` en cada sesión. Con la 0.20.4, `algo` no se carga en ninguno de los tres runners de la CI, y crear un índice `fts` hace fallar la CLI en mi máquina Windows; la CLI 0.19.1 ejecuta ambas.
- Los algoritmos se ejecutan sobre un grafo proyectado con nombre, que la conexión conserva; una proyección puede filtrar sus tablas de nodos y de relaciones. Los algoritmos rechazan una proyección definida por una consulta Cypher, con `Binder exception: AA`.
- Las componentes fuertemente conexas encuentran ciclos, las débilmente conexas encuentran islas; `group_id` depende de offsets internos.
- PageRank no es un recuento de referencias: una referencia desde un nodo importante con pocas referencias pesa más.
- Las comunidades de Louvain cambian de un proceso a otro: guárdalas antes de publicarlas.
- Un índice FTS es BM25 con un stemmer, inglés por defecto, y stop words inglesas sea cual sea el stemmer. Las mayúsculas se normalizan, los acentos no.
- Las puntuaciones dependen de la tabla entera y cambian cuando cambia. Una búsqueda devuelve nodos, y un patrón de grafo puede continuar desde ellos.

## Ejercicios

Las soluciones están en [`cypher/07-exercises.cypher`](https://github.com/spareilleux/learn/blob/main/code/ladybugdb/cypher/07-exercises.cypher), y su salida en `cypher/expected/07-exercises.csv`: la CI las comprueba con el resto.

1. `GA.Core` está referenciado por 32 proyectos, `GA.Domain.Services` por 48, y sin embargo `GA.Core` tiene un rango mayor. Vuelve a calcular ambos rangos a partir de los rangos de los proyectos que los referencian, con la fórmula de PageRank: `(1 - d) / N + d × Σ rank(a) / out_degree(a)`, con `d = 0.85` y `N` el número de proyectos.

<details>
<summary>Solución</summary>

[Líneas 13-29](https://github.com/spareilleux/learn/blob/0147f10/code/ladybugdb/cypher/07-exercises.cypher#L13-L29):

```cypher
ALTER TABLE Project ADD rank DOUBLE;
CALL page_rank('Deps') WITH node, rank SET node.rank = rank RETURN count(*) AS ranked;
MATCH (a:Project)-[:REFERENCES]->(b:Project {name: 'GA.Core'})
RETURN a.name, round(a.rank, 4) AS rank, COUNT { MATCH (a)-[:REFERENCES]->(:Project) } AS out_degree
ORDER BY rank DESC, a.name
LIMIT 3;
MATCH (p:Project)
WITH count(*) AS n
MATCH (a:Project)-[:REFERENCES]->(b:Project)
WHERE b.name IN ['GA.Core', 'GA.Domain.Services']
WITH n, b, a, COUNT { MATCH (a)-[:REFERENCES]->(:Project) } AS out_degree
// n + sum(...) en una sola expresión falla cuando n no se devuelve también por sí solo: primero la suma, el cálculo en la cláusula siguiente
WITH n, b, count(*) AS referenced_by, sum(a.rank / out_degree) AS received
RETURN b.name, referenced_by, round(b.rank, 4) AS rank, round((1 - 0.85) / n + 0.85 * received, 4) AS recomputed
ORDER BY rank DESC;
MATCH (p:Project)
RETURN round(sum(p.rank), 4) AS total, round(min(p.rank), 6) AS lowest;
```

```text
┌────────────────────┬──────────┬────────────┐
│ a.name             │ rank     │ out_degree │
│ STRING             │ DOUBLE   │ INT64      │
├────────────────────┼──────────┼────────────┤
│ GA.Domain.Core     │ 0.047700 │ 2          │
│ GA.Domain.Services │ 0.024300 │ 5          │
│ GA.Business.DSL    │ 0.011800 │ 3          │
└────────────────────┴──────────┴────────────┘
┌────────────────────┬───────────────┬──────────┬────────────┐
│ b.name             │ referenced_by │ rank     │ recomputed │
│ STRING             │ INT64         │ DOUBLE   │ DOUBLE     │
├────────────────────┼───────────────┼──────────┼────────────┤
│ GA.Core            │ 32            │ 0.044100 │ 0.044100   │
│ GA.Domain.Services │ 48            │ 0.024300 │ 0.024300   │
└────────────────────┴───────────────┴──────────┴────────────┘
┌──────────┬──────────┐
│ total    │ lowest   │
│ DOUBLE   │ DOUBLE   │
├──────────┼──────────┤
│ 0.353400 │ 0.001351 │
└──────────┴──────────┘
```

`GA.Domain.Core`, el primer proyecto, solo referencia dos proyectos, y `GA.Core` es uno de ellos: la mitad del rango más alto, por 0,85, va a `GA.Core`. De los 48 proyectos que referencian `GA.Domain.Services`, a 29 no los referencia nadie: aplicaciones, demos y pruebas con el rango mínimo, repartido entre todas sus referencias. La fórmula devuelve ambos rangos con cuatro decimales.

`CALL … WITH node, rank SET node.rank = rank` guarda el resultado del algoritmo en la tabla: las consultas posteriores leen el rango de cualquier proyecto, no solo del nodo que devuelve el algoritmo. El total, 0,3534 en lugar de 1, muestra que el rango de los 25 proyectos que no referencian nada, como `GA.Core`, no se redistribuye: compara rangos dentro de un grafo, no entre grafos. El rango más bajo, 0,001351, es `(1 - 0.85) / 111`, el rango de un proyecto al que nadie referencia.

`(1 - 0.85) / n + 0.85 * sum(…)` en el `RETURN` falla con `Cannot evaluate expression with type AGGREGATE_FUNCTION.` cuando `n` viene de un `WITH` anterior y no es también una columna por sí sola, una clave de agrupación. De ahí el segundo `WITH`.

</details>
