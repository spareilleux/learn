## Las tres herramientas

| Rust | Función | C# | Java |
|---|---|---|---|
| `rustup` | instala y actualiza las cadenas de herramientas | instalador del SDK de .NET / [`global.json`](https://learn.microsoft.com/dotnet/core/tools/global-json) | [SDKMAN!](https://sdkman.io/), instaladores del JDK |
| `cargo` | compilar, ejecutar, probar, añadir dependencias | [CLI de `dotnet`](https://learn.microsoft.com/dotnet/core/tools/) | [Maven](https://maven.apache.org/) / [Gradle](https://gradle.org/) |
| [crates.io](https://crates.io/) | registro público de paquetes | [NuGet](https://www.nuget.org/) | [Maven Central](https://central.sonatype.com/) |
| `rustc` | el compilador (Cargo lo invoca por ti) | [Roslyn](https://learn.microsoft.com/dotnet/csharp/roslyn-sdk/) (`csc`) | [`javac`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html) |

## Instalación

Rust se instala con [rustup](https://rustup.rs) en todos los sistemas operativos. Rust usa el **enlazador** (linker) de la plataforma, así que cada sistema necesita también sus herramientas nativas de compilación de C.

<Tabs syncKey="os">
<TabItem label="Windows">

```powershell
winget install Rustlang.Rustup
```

O descarga `rustup-init.exe` desde [rustup.rs](https://rustup.rs). La cadena de herramientas predeterminada apunta a MSVC, así que también necesitas las **[Visual Studio C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)** (el enlazador); `rustup-init` ofrece instalarlas si faltan. Después, abre una terminal nueva para que `cargo` esté en el `PATH`.

</TabItem>
<TabItem label="Linux / WSL">

```bash
sudo apt install build-essential        # el enlazador de C (Debian/Ubuntu; si no, el paquete de tu distribución)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"                    # o abre un shell nuevo
```

**En WSL**, instala Rust *dentro* de la distribución Linux, no con el instalador de Windows, y guarda tus proyectos en el sistema de archivos de Linux (`~/src/...`), no bajo `/mnt/c`: ahí las compilaciones son mucho más rápidas. [VS Code](https://code.visualstudio.com/docs/remote/wsl) y [RustRover](https://www.jetbrains.com/rust/) pueden abrir directamente una carpeta de WSL.

</TabItem>
<TabItem label="macOS">

```bash
xcode-select --install                  # las herramientas de línea de comandos de Apple, que incluyen el enlazador
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"                    # o abre una terminal nueva
```

</TabItem>
</Tabs>

Después, en cualquier sistema:

```bash
rustc --version   # rustc 1.94.0 (4a4ef493e 2026-03-02)
cargo --version   # cargo 1.94.0 (85eff7c80 2026-01-15)
rustup update     # actualizar a la última versión estable
```

:::note[Ningún runtime que instalar]
Rust compila a un ejecutable nativo. No hay CLR ni JVM que distribuir: la compilación release de «Hello, world!» es un único archivo, de unos 130 KB como `.exe` en Windows y de unos 430–460 KB en macOS y Linux (medido por la CI del curso).
:::

## Crear un proyecto

```bash
cargo new hello
cd hello
cargo run
```

Las salidas de Linux y macOS provienen de los runners de la CI del curso, que usan un Cargo más reciente que añade la línea `note:`.

`cargo new` también ejecuta `git init` y escribe un `.gitignore`. La estructura:

```text
hello/
├── Cargo.toml      ← like .csproj or pom.xml
├── src/
│   └── main.rs     ← entry point (a library would have src/lib.rs)
└── .gitignore
```

```toml
# Cargo.toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
```

```rust
// src/main.rs
fn main() {
    println!("Hello, world!");
}
```

- `println!` termina en `!` porque es una **macro**, no una función (comprueba la cadena de formato en tiempo de compilación).
- La **edición** (`2024`) es como [`<LangVersion>`](https://learn.microsoft.com/dotnet/csharp/language-reference/configure-language-version) o [`--release`](https://openjdk.org/jeps/247): activa cambios del lenguaje sin romper los crates más antiguos, que siguen compilando con su propia edición.

:::note[Las salidas de este curso]
Los errores del compilador y las salidas de los programas de las lecciones se capturaron en Windows. En Linux y macOS son idénticos salvo por las rutas: `/` en lugar de `\`, y sin extensión `.exe` ni `.dll`. La CI del curso también compila y ejecuta cada ejemplo en Linux y macOS.
:::

## Comandos del día a día

| Tarea | Cargo | dotnet | Maven |
|---|---|---|---|
| Nueva aplicación | `cargo new app` | `dotnet new console` | `mvn archetype:generate` |
| Nueva biblioteca | `cargo new --lib lib` | `dotnet new classlib` | — |
| Comprobación rápida de tipos | `cargo check` | — | — |
| Compilar (debug) | `cargo build` | `dotnet build` | `mvn compile` |
| Compilar (release) | `cargo build --release` | `dotnet build -c Release` | `mvn package` |
| Ejecutar | `cargo run` | `dotnet run` | `mvn exec:java` |
| Probar | `cargo test` | `dotnet test` | `mvn test` |
| Añadir una dependencia | `cargo add rand` | `dotnet add package` | editar `pom.xml` |
| Formatear | `cargo fmt` | [`dotnet format`](https://learn.microsoft.com/dotnet/core/tools/dotnet-format) | plugin [Spotless](https://github.com/diffplug/spotless) |
| Análisis estático (lint) | [`cargo clippy`](https://doc.rust-lang.org/clippy/) | [analizadores de Roslyn](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/overview) | [Error Prone](https://errorprone.info/), [SpotBugs](https://spotbugs.github.io/) |
| Documentación de la API | `cargo doc --open` | [documentación XML](https://learn.microsoft.com/dotnet/csharp/language-reference/xmldoc/) + [DocFX](https://dotnet.github.io/docfx/) | [`javadoc`](https://docs.oracle.com/en/java/javase/25/javadoc/) |

:::tip[Usa `cargo check` todo el tiempo]
`cargo check` ejecuta toda la comprobación de tipos y el borrow checker, pero se salta la generación de código. Es mucho más rápido que una compilación, y es lo que hace tu editor ([rust-analyzer](https://rust-analyzer.github.io/)) con cada pulsación de tecla.
:::

## Dependencias

```bash
cargo add rand
```

```toml
[dependencies]
rand = "0.10.2"
```

- `"0.10.2"` significa **compatible con 0.10.2** ([caret de SemVer](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#caret-requirements)), no «exactamente 0.10.2».
- Las versiones exactas resueltas se escriben en [`Cargo.lock`](https://doc.rust-lang.org/cargo/guide/cargo-toml-vs-cargo-lock.html) — como [`packages.lock.json`](https://learn.microsoft.com/nuget/consume-packages/package-references-in-project-files#locking-dependencies) o un [archivo de bloqueo de Gradle](https://docs.gradle.org/current/userguide/dependency_locking.html). Súbelo al control de versiones en las aplicaciones.
- Las compilaciones debug y release van a `target/debug` y `target/release` (como `bin/Debug` y `bin/Release`).

## Puntos clave

- `rustup` gestiona los compiladores, `cargo` hace todo lo demás y crates.io aloja los paquetes.
- Cada sistema necesita su enlazador nativo: Visual Studio Build Tools, `build-essential` o las [herramientas de línea de comandos de Xcode](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools/).
- `Cargo.toml` + `Cargo.lock` ≈ `.csproj` + archivo de bloqueo / `pom.xml`.
- `cargo check` para una respuesta rápida, `cargo build --release` para binarios optimizados.

## Ejercicios

1. Crea un proyecto llamado `dice`, añade el crate [`rand`](https://docs.rs/rand) y busca en `Cargo.lock` qué versión se resolvió realmente.

<details>
<summary>Solución</summary>

<Tabs syncKey="os">
<TabItem label="Windows">

```powershell
cargo new dice
cd dice
cargo add rand
cargo build
Select-String -Path Cargo.lock -Pattern 'name = "rand"' -Context 0,1
```

</TabItem>
<TabItem label="Linux / WSL">

```bash
cargo new dice
cd dice
cargo add rand
cargo build
grep -A1 'name = "rand"' Cargo.lock
```

</TabItem>
<TabItem label="macOS">

```bash
cargo new dice
cd dice
cargo add rand
cargo build
grep -A1 'name = "rand"' Cargo.lock
```

</TabItem>
</Tabs>

`Cargo.toml` contiene el requisito que pediste; `Cargo.lock` contiene la versión exacta (y cada dependencia transitiva) que se eligió.

</details>

2. ¿Cuál es la diferencia entre `cargo check` y `cargo build`, y cuándo usarías cada uno?

<details>
<summary>Solución</summary>

`cargo check` comprueba los tipos y los préstamos sin producir un binario, así que es rápido — úsalo mientras editas. `cargo build` además genera código máquina — úsalo cuando necesites ejecutar el programa, y `cargo build --release` para una versión optimizada.

</details>
