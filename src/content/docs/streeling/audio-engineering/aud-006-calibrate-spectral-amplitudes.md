## The project question

A GA audio analyst doubles an analysis window and sees a stronger spectral peak. Did the guitar become louder, or did the measurement change? Before a spectral value enters an improvement loop, give it a reference and test it on a signal with known amplitude. This lesson builds that calibration; [AUD-003](../../audio-engineering/aud-003-transient-preservation-gate/) covers transient placement and denoising instead.

The pinned [IX spectrogram implementation](https://github.com/GuitarAlchemist/ix/blob/bd1336b7c4045e427dcdbe80b102790e45da5ce1/crates/ix-signal/src/spectral.rs#L32-L54) takes magnitudes of windowed transforms. With its logarithmic option it applies `20*log10(max(magnitude,1e-10))`. The [window implementation](https://github.com/GuitarAlchemist/ix/blob/bd1336b7c4045e427dcdbe80b102790e45da5ce1/crates/ix-signal/src/window.rs#L10-L15) uses a symmetric Hann. Neither step divides by the window sum. Source inspection establishes that formula; it does not establish a result from a running IX service.

Read the [calibration measurements](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/spectral-views-2026-10-22/calibration.json) and [analysis receipt](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/spectral-views-2026-10-22/execution.json). Temporary analysis used [NumPy's real-input FFT](https://numpy.org/doc/stable/reference/generated/numpy.fft.rfft.html) with an unscaled forward transform and its [symmetric Hann window](https://numpy.org/doc/stable/reference/generated/numpy.hanning.html). Installed package versions are in the receipt; the current documentation can describe a newer release.

## 1. Keep the physical input fixed while changing the analysis

The constructed cosine has peak amplitude 0.25 and frequency 689.0625 Hz at sample rate 44100 Hz. It lies at bin 32 for window length 2048 and bin 64 for length 4096. Both cases therefore analyze an integer number of cycles. The symmetric Hann is `w[n] = 0.5 - 0.5*cos(2*pi*n/(N-1))`; its sum is approximately 1023.5 and 2047.5 in these cases.

| Window length | Tone bin | Raw magnitude | Peak-amplitude estimate |
|---|---|---|---|
| 2048 | 32 | 127.9375151793639 | 0.25000002966167834 |
| 4096 | 64 | 255.93750379229243 | 0.25000000370431497 |

The raw-magnitude dB difference is about 6.02272037 dB. That difference follows the changed analysis gain. It is not evidence of a gain change in the constructed input. The small residual error after normalization comes from this finite symmetric-window calculation; do not round it into a claim of exact equality.

### Practice exercise 1: diagnose the apparent improvement

An agent calls the second row a roughly 6 dB stronger guitar. What remained fixed, what changed, and which result challenges that interpretation?

> **Answer:** Peak amplitude 0.25, frequency 689.0625 Hz and sample rate 44100 Hz remained fixed. Window length changed from 2048 to 4096, changing the window-sum gain. The normalized estimates both recover approximately 0.25 while raw magnitudes nearly double. The roughly 6 dB difference describes this measurement change, not a new guitar render or louder input.

## 2. State which amplitude the formula estimates

For an isolated real cosine at an interior coherent bin, use `A[k] = 2*abs(X[k])/sum(w)`. The real cosine has positive- and negative-frequency contributions; retaining one side requires the factor 2 for this amplitude estimate. The tests recover the declared peak amplitude within absolute tolerance `1e-6`. Selected complex transform values were also checked by direct summation with absolute tolerance `1e-10`, rather than checking only a rounded chart label.

For the amplitude reference 1, the logarithmic estimate is `20*log10(A/1)`. A peak amplitude of 0.25 is about -12.0412 dB relative to that unit peak reference. This formula describes peak amplitude under a declared transform/window estimator. It is not an RMS, loudness, integrated broadband power or power spectral density estimate. Closely spaced guitar partials and off-bin components need additional analysis before a single-bin value can stand for an individual partial's amplitude.

### Practice exercise 2: recover the amplitude

Using the first row, calculate `2*127.9375151793639/1023.5`. What value and logarithmic reference should accompany the answer? Can you label it a power spectral density?

> **Answer:** The estimate is approximately 0.25000003, within `1e-6` of the constructed 0.25 peak amplitude. Relative to unit peak amplitude its value is approximately -12.0412 dB. The declared interior-bin amplitude estimator supplies no per-hertz power normalization, so a power spectral density label would be unsupported.

## 3. Do not double the endpoints

For an even transform length, DC and Nyquist are not paired with distinct retained negative-frequency bins. Use `A[k] = abs(X[k])/sum(w)` at those endpoints. The separate controls use a constant 0.25 and the alternating sequence `0.25*(-1)^n`. Both recover 0.25 without doubling. Applying the interior-bin rule to either endpoint would instead report approximately 0.5, a deliberately rejected result.

### Practice exercise 3: catch the endpoint error

At length 2048 the DC control has raw magnitude 255.875 and window sum 1023.5. Calculate the correct and incorrectly doubled amplitudes. Would the same endpoint rule apply at Nyquist?

> **Answer:** `255.875/1023.5 = 0.25`; incorrectly doubling gives 0.5. Nyquist also uses the undoubled endpoint rule for this even-length real transform. A blanket factor 2 would fail both calibration controls.

## 4. Bind the decoder as well as the transform

The retained [baseline WAV](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/guitar-runtime-2026-10-22/baseline.wav) and [candidate WAV](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/guitar-runtime-2026-10-22/candidate.wav) are mono PCM16, with 176400 samples at 44100 Hz. The new analysis decodes each signed integer with denominator 32768. The earlier exporter used a 32767 multiplier when creating those WAVs. Those are different steps with separately declared conventions; this analysis does not recover the pre-quantization native floating-point buffers.

The WAV hashes, decoder convention, selected matrix cells and complete-frame coordinates are in the [coordinate record](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/spectral-views-2026-10-22/coordinates.json). Keep those inputs fixed when comparing a baseline with a candidate. A decoder or normalization change inside one arm would confound the comparison.

### Practice exercise 4: keep the quantities separate

An analyst divides PCM16 samples by 32768 and then labels the array “the exact original native float samples because the exporter used 32767.” What should the record say instead?

> **Answer:** It contains decoded, quantized PCM16 samples using the declared 32768 denominator. The export multiplier 32767 describes an earlier quantization step and does not undo information loss or identify the original floats. Retain the WAV hash and both conventions; do not claim native-buffer equality from this decoded array.

## 5. Use calibration to protect the decision

The earlier [decay experiment](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/guitar-runtime-2026-10-22/results.json) improved its declared error by about 0.11416615 dB against a required improvement of 1 dB. It failed that gate. A calibrated plot does not replace the declared measure or supply a listener preference. [DV-009](../../data-visualization/dv-009-compare-spectrogram-color-scales/) uses the same retained samples to show how a display can conceal an actual constructed gain difference.

### Practice exercise 5: decide what the evidence accepts

An agent says the candidate looks better after changing window normalization, so its failed decay gate can be marked passed. What should the improvement loop retain, reject and test next?

> **Answer:** Retain the calibrated analysis with its WAV hashes, decoder, window and reference. Reject changing the recorded gate verdict: approximately 0.11416615 dB is below the required 1 dB. If a different musical property matters, declare a separate measure and acceptance rule before a new comparison, then test it. Neither this calibration nor a picture supplies human listening approval.
