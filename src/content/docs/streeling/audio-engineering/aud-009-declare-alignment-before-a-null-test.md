## The project question

Two buffers cancel after an agent shifts and rescales one. Were the original buffers identical? [AUD-005](../../audio-engineering/aud-005-pcm-guards-and-format-boundaries/) separates PCM guards and formats; [AUD-008](../../audio-engineering/aud-008-measure-a-filter-with-paired-input-and-output/) keeps input and output paired. Here the comparison must preserve its transformations as results.

## 1. Declare clock, lag direction and complete support

The [fixed samples](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/audio-comparison-2026-10-23/null-comparison.json) are authored real values:

```text
x = [0, .25, -.25, .5, -.5, .25, 0, -.25]
y = [0, 0] + .5*x
Fs = 8000 Hz
y[n+2] = .5*x[n] for n = 0..7
```

The reference has 8 frames; the delayed signal has 10. The declared reference target is all 8 frames, paired with y frames 2 through 9. The delay is 2/8000 seconds = .25 ms. This teaching clock is not a measured browser rate or hardware latency.

### Exercise 1 — Make the pairing reproducible

State the target, frame correspondence and delay direction. Is .25 ms an observed improvement in latency?

> **Answer.** Pair x frame n with y frame n+2 for every reference frame from 0 through 7. The authored y is delayed by 2 frames. This covers the complete declared reference target and accounts for the two leading frames separately. The .25 ms value follows from the stipulated clock; it is neither measured latency nor an improvement.

## 2. Report unadjusted and adjusted residuals

For any declared residual vector r, RMS is the square root of its mean square. The reference RMS is about .306186218. Comparing x with the first 8 frames of y at the original origin gives a residual RMS of about .275992527. Aligning the declared delay but keeping unity gain gives about .153093109.

The first comparison is an explicitly cropped, original-origin diagnostic, not complete coverage of the delayed signal. It must not silently become the final aligned target.

### Exercise 2 — Explain the changed question

Why can the delay-aligned residual be smaller even though no original sample changed?

> **Answer.** The frame pairing changed. After alignment the signal is half the reference, so the difference has half the reference RMS. This removes the stipulated shift from the comparison question, not from the original signal history. Keep both residuals, their supports and the delay instead of claiming alignment preserved the original timing.

## 3. A fitted null does not prove original equality

On the complete aligned target, fit a real scalar with the reference as predictor:

```text
g_hat = sum(x[n]*y[n+2])/sum(x[n]*x[n]) = .5
residual[n] = y[n+2] - g_hat*x[n] = 0
20*log10(g_hat) = -6.020599913 dB
```

The declared delay-and-gain model fits exactly in real arithmetic. It has removed two differences that may matter to the user: timing and level. This says nothing about native/Wasm float-byte identity, PCM16 identity or listening preference.

### Exercise 3 — Write a truthful verdict

Can the zero fitted residual be reported as “unchanged audio”? Include the delay and gain in a replacement verdict.

> **Answer.** Report exact agreement of the authored samples after the declared 2-frame alignment and fitted gain .5, about -6.020599913 dB. The original signals differ in support, timing and level. A fitted zero establishes only the stated transformed comparison on its full target. It does not demonstrate unchanged original audio, bit identity or measured latency reduction.

## 4. Silence and censored tails need separate statuses

For two silent 8-frame vectors, the raw residual is zero but the gain-fit denominator is zero: gain is undefined. Raw silence equality remains a valid statement.

For a tail control, start with the aligned .5*x and add .125 to its last frame. Using the prescribed gain .5, the first 6 frames have zero residual, but only 6/8 = .75 of the declared target was checked. The complete residual RMS is about .044194174. That is a prescribed-gain check; do not silently refit the changed tail.

### Exercise 4 — Reject two invalid passes

Should undefined fitted gain make silent raw equality false? Can the zero residual from the first 6 frames certify the full 8-frame target?

> **Answer.** No to both. Silent gain fitting is undefined while direct raw comparison is still meaningful. In the tail case the omitted difference makes the full residual nonzero. Keep checked frame count, target frame count, missingness and transformation policy. This target requires all 8 frames; the example does not establish a universal minimum-coverage threshold for other tasks.

## 5. Read the existing runner before proposing a pipeline

The pinned [Learn runner](https://github.com/spareilleux/learn/blob/49ad4cf7db680f031b3a3fb5b6ee118464ad099f/code/streeling/guitar-runtime/run.mjs) separately handles raw float bytes, PCM16 and rounded half-open RMS windows. It uses known onset offsets for its decay comparison; it does not implement this new delay/gain fitting procedure. Its [provenance](https://github.com/spareilleux/learn/blob/49ad4cf7db680f031b3a3fb5b6ee118464ad099f/code/streeling/guitar-runtime/source.json) pins an older engine than the newly inspected GA source. The retained failed decay gate is unchanged.

### Exercise 5 — Define a source-assisted comparison

What would an actual native/Wasm comparison record need before these ideas become an agentic DSL?

> **Answer.** Preserve engine and runner revisions, sample format, channel layout, clocks, excitation, full buffer extents, target support, lag direction, fitted or prescribed gain, raw metrics, adjusted metrics, missing frames and computational cost. Inspect where the current runner serializes floats and converts PCM16. Compare a small explicit record and direct subtraction first. Byte identity, transformed agreement, latency and listening require separate evidence. No production pipeline, new runtime run or user benefit was demonstrated here.
