A guitar exercise can have the right number of written notes and still end at the wrong time if its tuplet ratio is inverted. Meter grouping does not resolve that ratio, and a bracket label alone may not carry every duration field. This lesson builds an exact rational timeline before conversion to seconds. It adds local note-duration semantics to the prerequisite's beat-unit distinction, so a future notation or scheduling handoff has a manual baseline to preserve.

## Read the retained evidence

Read the retained timed-event packet's absolute beat coordinates. It uses explicit times rather than inferring them from a decorative label. MusicXML's time-modification element distinguishes actual and normal note counts and describes their cumulative sounding effect. More detailed nested notation needs additional information. Our example deliberately uses one undotted, non-nested group and does not claim a complete importer or export implementation.

### Exercise 1

Let resolution be `480` ticks per quarter and base duration `1/2` quarter. The unmodified note therefore lasts `240` ticks. Keeping the base type separate from its modifier prevents the word eighth from being treated as a final sounding duration regardless of context. The reference unit is a quarter, not an unspecified beat label.

What is the base duration in ticks?

<details><summary>Answer 1</summary>

It is `240` ticks, from `480*(1/2)`. That is the unmodified duration, before the declared tuplet ratio.

</details>

### Exercise 2

Use actual count `3` and normal count `2`: the written actual notes occupy the time of the normal count. Per-note duration is `Q*(base_num/base_den)*(normal/actual)`, giving `160` ticks. The ratio multiplies time, so using actual divided by normal would lengthen the notes rather than fit the intended group into its allotted span.

What duration does each modified note receive?

<details><summary>Answer 2</summary>

Each receives `160` ticks. The time multiplier is `2/3`, applied to the unmodified `240` ticks.

</details>

### Exercise 3

There are `3` equal notes, totaling `480` ticks or `1` quarter. Onsets relative to the group start are `[0,160,320]` ticks, ending at `480`. Exact arithmetic makes this closure visible. At other resolutions a rational result may not be an integer tick; rounding each note separately could move the endpoint and needs a separate policy.

Give the onsets and group endpoint.

<details><summary>Answer 3</summary>

The onsets are `[0,160,320]` ticks and the endpoint is `480`. This group exactly fills `1` quarter under the declared resolution.

</details>

### Exercise 4

The negative control swaps actual and normal fields, retaining note count `3` and the same base duration. Each note becomes `360` ticks; the group totals `1080` ticks, or `2.25` quarters. A check that only counts written notes would pass this changed interpretation, even though its scheduled endpoint is substantially different.

What does the inverted-field control produce?

<details><summary>Answer 4</summary>

It produces `360` ticks per note and `1080` ticks total, equal to `2.25` quarters. The ratio fields are semantic inputs, not interchangeable annotations.

</details>

### Exercise 5

A later tempo map converts these score coordinates to seconds; it cannot repair a wrong tuplet duration. Preserve base unit, actual/normal counts, dots if present and exact time support before projecting to integer output ticks. A future agent can compare the proposed timeline with this rational baseline without claiming that a printed bracket proves playback fidelity.

What would falsify a claim to preserve this tuplet's duration?

<details><summary>Answer 5</summary>

A timeline ending anywhere other than `480` ticks for the main case contradicts its declared model. The control's `1080` ticks is a concrete failure witness if presented as the main result.

</details>
