A proposed agent controller accumulates an error while the action it requests is capped. When the error reverses, its stored demand may still point strongly in the old direction. The convergence prerequisite has no saturation. This lesson adds an explicit cap and compares stored integral state with applied command. Neither sequence is a measured GA controller trace.

The primary anti-windup documentation distinguishes output limiting from methods that affect the internal integrator. Read its conditional-integration discussion. Our authored rule is deliberately stricter than a practical tuned controller: reject an entire increment when its candidate exceeds a limit and the current error pushes farther outward. This makes the comparison easy to audit and exposes a cost of the rule. It is not presented as the product's exact implementation.

The naive version stores every candidate and clips only the applied command. The cap prevents the command from exceeding the stated range but leaves the internal state growing. A later negative error reduces that state without necessarily changing the saturated output. Keeping only the output trace would hide the difference between the requested and applied quantities. A receiving operator needs both to understand why the command remains at its limit.

The conditional version rejects outward increments and therefore avoids the stored excess in this example. But its coarse update also leaves usable range unused: the first candidate jumps past the cap and the rule rejects it entirely. That behavior is a retained limitation, not an implementation success to conceal. A different rule might project the state to the limit, use back-calculation or choose another update policy; each would require a new declared recurrence.

For the source-assisted task, contrast the prerequisite's unconstrained iteration with the documentation's saturation discussion. Build a manual table with candidate, stored state and applied command as distinct columns. Ask an assistant to compute the same table and explain the unused-range counterargument. Reject the proposed controller if it claims stability from clipping alone, silently substitutes another anti-windup rule, or describes these authored values as live resource measurements.
