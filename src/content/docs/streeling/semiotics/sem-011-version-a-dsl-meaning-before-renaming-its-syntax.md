## Project question

A BRUTAL block retains its familiar name but starts generating different geometry. Has an old scene instruction retained its meaning? Conversely, can a renamed token still denote the same operation? The pinned model explicitly represents block name and version. This lesson uses a finite interpretation table to distinguish an alias from a semantic change before anyone proposes rewriting scene descriptions.

The direct baseline is a small handwritten calculation and a source-location table; an agent may help locate a definition, but its summary must be checked against that definition. Do not introduce a new language or automation merely to perform this finite comparison.

In the old CPU calculation, two column versions emit different box counts at the same authored parameter. Use the table as a semantic witness: a change in the denoted result defeats an unchanged-meaning claim for that input. It does not prove all inputs differ or define every aspect of scene equivalence. A syntactic alias preserves the same version binding, while silently rebinding an old token to a new version changes interpretation. Keep old and new meanings addressable together when reproducibility matters. This is a source-assisted migration argument, not a new runnable language or a theorem of backward compatibility.

## Fixed case and assumptions

```text
n=4
meaning_v1(n)=3+2*n; result_v1=11
meaning_v2(n)=3+4*n; result_v2=19
difference=19-11=8
old_token="column@1"; alias="pillar@1"
alias_binding="column@1"; alias_result=11
control_n=0; control_v1=3; control_v2=3
```

## Corrected exercises

### Exercise 1

Evaluate both meanings at the declared input.

> **Answer:** The results are `11` and `19`, differing by `8` boxes. These counts come from the pinned old calculation, not a new host execution.

### Exercise 2

Does the alias preserve this selected meaning?

> **Answer:** Yes, if it binds to `column@1`, it still gives `11`. A different display token can denote the same versioned operation.

### Exercise 3

Silently bind the old token to the second meaning. Is syntax preservation sufficient?

> **Answer:** No. The same old token now gives `19` rather than `11`. Unchanged spelling cannot establish unchanged denotation.

### Exercise 4

What does the zero-input control establish?

> **Answer:** Both formulas give `3`. Equality on that input would miss the change, so choose a distinguishing supported input before claiming equivalence.

### Exercise 5

Does equal box count establish full scene equivalence?

> **Answer:** No. Positions, dimensions, materials, seed and semantic bindings may differ. Box count is a witness that can reject equivalence, not a complete scene identity.

The zero-input control is algebraic only; it is not asserted to be an admissible BRUTAL request.
