A teammate sees repeated objects in the saved [Godot](https://docs.godotengine.org/en/4.6/classes/class_meshinstance3d.html) weave and asks, “Which objects share data, and what would a shared edit affect?” Answering requires a graph whose edges express resource references. ## 1. Count containment before sharing

For “What belongs under this scene root?”, choose the hierarchy: vertices are scene nodes and directed edges mean parent to child. Counting declared types, it contains 253 nodes: 37 [`Node3D`](https://docs.godotengine.org/en/4.6/classes/class_node3d.html) nodes, including the root and 36 crossing parents, plus 72 each of [`MeshInstance3D`](https://docs.godotengine.org/en/4.6/classes/class_meshinstance3d.html), [`StaticBody3D`](https://docs.godotengine.org/en/4.6/classes/class_staticbody3d.html), and [`CollisionShape3D`](https://docs.godotengine.org/en/4.6/classes/class_collisionshape3d.html). Each crossing contains a warp branch and a weft branch, with a mesh, body, and shape in each.

The file also declares 6 shared subresources: 2 meshes, 2 collision shapes, and 2 materials. A [Resource](https://docs.godotengine.org/en/4.6/classes/class_resource.html) holds data; its declaration is not another scene node. Counting declarations together with nodes would mix object roles. The [prior runtime report](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/weave-scene-2026-10-22/good-godot-report.json) records loaded counts and sharing; this extraction inspects the saved representation.

### Exercise 1 — Separate the inventories

Someone counts 259 scene nodes by adding the resources. Correct the count and explain the 37 `Node3D` nodes.

> **Answer:** There are 253 scene nodes and 6 separate resources. The 37 `Node3D` nodes comprise 1 root and 36 crossing parents. Resource declarations contribute no extra hierarchy vertices.

## 2. Make references the relation

For “Which scene nodes refer to shared data?”, build a directed bipartite graph. The left side contains scene nodes with a `mesh`, `material_override`, or `shape` reference; the right side contains declared `SubResource` objects. A property reference supplies one directed edge, labeled by that property. Properties are edge labels, not additional vertices.

All 72 mesh instances have a mesh edge and a material edge; all 72 collision-shape nodes have a shape edge. Thus there are 144 left vertices, 6 right vertices, and `72 * 2 + 72 = 216` edges. Each resource has indegree 36. The 109 other hierarchy nodes lack these selected references and are excluded from this graph. Exclusion says nothing about their importance to the scene.

For example, `w0-f0/warp` references `BoxMesh_jk82c` through `mesh`. This is a saved data relation, not an observed service call or a collaboration between authors.

### Exercise 2 — Audit the bipartite count

Why are there 144 left vertices rather than 253 or 216? Give the edge count and every resource's indegree.

> **Answer:** Only 72 mesh instances and 72 collision-shape nodes participate. Multiple properties can leave the same vertex. There are 216 edges, and each of the 6 resources has indegree 36.

## 3. Project only the question you need

For “Which mesh instances share the same mesh?”, retain the 72 mesh-instance vertices. Join 2 different vertices by one undirected edge exactly when their `mesh` properties name the same saved [`BoxMesh`](https://docs.godotengine.org/en/4.6/classes/class_boxmesh.html). Ignore materials, shapes, and hierarchy links.

The projection has 2 components, each a clique of 36 vertices: every warp shares one mesh, every weft the other. Each vertex has degree 35. Counting unordered pairs gives `2 * (36 * 35 / 2) = 1260` edges. These edges summarize shared references; no 1260-edge structure was stored as scene hierarchy. Projection also hides which resource caused each connection, so retain the original reference graph for diagnosis.

### Exercise 3 — Count without double counting

Calculate the mesh projection's degree, component sizes, and edge count. Why divide by 2?

> **Answer:** Degree 35; component sizes 36 and 36; 1260 edges. Within each clique, counting neighbors counts each undirected pair twice, so division by 2 corrects it.

## 4. Bound a hypothetical cut

Delete one `BoxMesh` vertex from the analytical reference graph. Its 36 incident edges disappear, leaving `216 - 36 = 180` edges. If someone actually removed that declaration while retaining the scene's property assignments, 36 mesh references would lack their target. That conditional statement identifies repair scope; no scene was edited and no engine failure was observed.

Those mesh nodes also reference materials. Removing a mesh resource does not remove their material edges or their hierarchy membership. Likewise, a graph cut cannot certify a metadata error: crossing IDs and resource identity answer different questions. Runtime resource ObjectIDs are ephemeral and are not source crossing IDs.

### Exercise 4 — Write the bounded result

State the remaining edge count and affected-reference count after the hypothetical cut. May you report a failed Godot load?

> **Answer:** 180 analytical reference edges remain; 36 mesh references would need repair if the declaration were actually deleted without updating them. A failed load is unobserved and cannot be reported.

## 5. Ask for the missing experiment

Sharing a resource suggests where a data edit could propagate, but this extraction measures neither propagation nor rendering cost. [MeshInstance3D](https://docs.godotengine.org/en/4.6/classes/class_meshinstance3d.html) and [MultiMesh](https://docs.godotengine.org/en/4.6/classes/class_multimesh.html) describe different representation choices. Several nodes referencing one mesh do not automatically establish MultiMesh instancing or draw-call batching. Documentation describes capabilities; it does not benchmark this scene.

To test an edit claim, use a scratch copy, specify a resource property mutation, compare every affected instance, and retain before/after receipts. To test performance, control scene, renderer, hardware, workload, and representation, then measure repeated comparable runs. The [lab README](https://github.com/spareilleux/learn/blob/main/code/streeling/weave-godot/README.md) documents the prior persistence experiment, whose scope is 36 saved crossings. None of these graphs establishes a general exporter or a node-UUID DSL requirement.

### Exercise 5 — Choose evidence for the claim

A proposal says “resource sharing improved GPU performance and a mesh edit changed every warp.” What evidence is missing?

> **Answer:** A controlled benchmark with measured rendering results, and a recorded resource mutation with instance comparisons. The static graph supports shared-reference counts only; both proposed empirical claims remain to verify.
