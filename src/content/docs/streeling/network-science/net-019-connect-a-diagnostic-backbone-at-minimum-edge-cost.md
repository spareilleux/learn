An observatory sketch needs a small diagnostic backbone connecting several components. Candidate links have stipulated setup costs. Choosing the cheapest link for every component separately can introduce cycles or leave groups disconnected. A spanning tree makes global connectivity explicit while avoiding redundant edges under this particular objective.

Enumerate edge subsets of the required tree size, reject disconnected subsets and compare their summed cost. For a connected undirected graph, a connected subset with that edge count is a tree. The small authored graph makes exhaustive comparison practical and independently checkable. Keep every minimum-cost tree if the data produce ties; endpoint names alone are not an authority for choosing among equivalent optima.

The control raises a link cost enough that another backbone becomes cheaper. The old tree stays connected, but it is no longer optimal under the revised costs. This is a cost-sensitivity result, not a measured network deployment. A tree has no redundant route when one of its edges fails, so minimum setup cost cannot certify resilience. The primary documentation also distinguishes disconnected inputs, which yield a forest rather than a complete spanning tree. A future topology DSL must retain those objective and connectivity premises.

## Corrected exercises

### Exercise 1

Find the fixed minimum backbone.

> **Answer:** Edges `[AB,BC,CD]` connect all nodes at cost `6`. Their subset is connected and has no cycle.

### Exercise 2

Apply the expensive-link control.

> **Answer:** The optimum becomes `[AB,BC,BD]`, cost `8`. Keeping the previous tree would cost `11`.

### Exercise 3

Does minimum cost imply a failover route?

> **Answer:** No. Removing any tree edge disconnects it. Resilience needs an additional connectivity objective or constraint.
