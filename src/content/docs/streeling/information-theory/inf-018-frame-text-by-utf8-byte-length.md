A handoff joins messages with a delimiter that can also appear inside a message. The receiver cannot infer boundaries from the joined text alone. Agreeing on verdict vocabulary does not repair that ambiguity. The preceding codebook course fixes meanings; this operation fixes where each encoded message ends.

RFC 8949 explicitly counts bytes for definite-length text strings and specifies UTF-8. Our decimal-length-and-colon notation borrows only that distinction; it is not CBOR encoding. Determine each payload’s UTF-8 byte count, write the length prefix, then consume exactly that many bytes. A delimiter inside a payload no longer acts as a separator under the declared rule.

The accented character makes a useful control because character count differs from byte count. Locale translation must preserve this literal fixture; replacing it with an ASCII word would remove the witness. Real framing also needs limits, malformed-prefix behavior and truncation handling, none of which this finite case implements. A proposed DSL must state its representation unit before calling a message boundary unambiguous.

### Exercise 1

Count the UTF-8 bytes.

<details><summary>Answer 1</summary>

The counts are `[2,3]` for `[é,A|B]`. A displayed character need not occupy a single byte.

</details>

### Exercise 2

Write the valid frame.

<details><summary>Answer 2</summary>

The frame is `2:é3:A|B`. Payload delimiters remain payload because the length determines each boundary.

</details>

### Exercise 3

Why is the naive joined text ambiguous?

<details><summary>Answer 3</summary>

`é|A|B` also fits messages `[é|A,B]`. The joined bytes alone do not identify which partition was intended.

</details>

### Exercise 4

Apply the character-count control.

<details><summary>Answer 4</summary>

Declared lengths `[1,3]` differ from `[2,3]`; `valid=false` and `frame=null`. Do not silently repair the prefix.

</details>

### Exercise 5

What remains before a streaming implementation is justified?

<details><summary>Answer 5</summary>

Malformed lengths, truncated input, size limits and error recovery need separate contracts and checks. No live decoder was exercised here.

</details>
