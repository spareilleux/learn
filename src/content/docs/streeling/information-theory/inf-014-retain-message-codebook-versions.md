> This lesson uses an authored fixed case and inspected sources. Counts, times, labels and signals are invented teaching inputs. Human technical review, fluent-language review, actual learner attempts, runtime execution, production adoption and publication decisions remain undecided.

A compact handoff replaces verdict words with small tags. Every tag arrives intact, yet the receiving agent reports the opposite verdict. The information-loss prerequisite asks which fields disappear from a summary. This lesson isolates a different failure: the same symbols have different meanings under two perfectly invertible codebooks. Nothing in a successful byte transfer establishes that sender and receiver selected the same interpretation.

The codebook version is part of the message context. Decode using the sender’s declared mapping to obtain the intended labels, then decode the unchanged tags using the receiver’s mapping. Count mismatches by position rather than comparing only totals. Reversing the mapping can preserve tag frequency and message length while changing every verdict. A checksum over tags would detect neither this stipulated disagreement nor a missing semantic version.

[Shannon](https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf)’s communication problem separates a selected message from its transmitted representation. Our case assumes an error-free channel and concentrates on the chosen mappings. [W3C](https://www.w3.org/TR/2013/REC-prov-dm-20130430/) provenance motivates retaining the identity of the entity that supplies a derivation rule. Neither reference defines a new GA message schema. The Learn parser’s separate metadata and body fields provide a concrete project representation to inspect, without claiming they implement these binary tags.

The control changes the receiver’s codebook selection while preserving every tag. This makes the missing agreement explicit and gives a direct manual baseline. A proposed DSL may abbreviate the mapping, but it must keep codebook identity recoverable and leave an unknown version unresolved. Guessing from a plausible verdict reverses the evidential direction: the desired meaning should not select the decoder after seeing the answer. No version migration or production compatibility policy is implemented here.

### Exercise 1

Decode the sent tags using the sender’s version.

<details><summary>Answer 1</summary>

The intended labels are `[fail,pass,pass]` under `v2`. The mapping, not the visual size of a tag, determines its meaning. Keep that version attached before comparing any verdict counts.

</details>

### Exercise 2

Decode the same tags using the receiver’s version and count disagreements.

<details><summary>Answer 2</summary>

The receiver obtains `[pass,fail,fail]` under `v1`. There are `3` positional mismatches. The tags themselves are unchanged, so byte integrity alone cannot distinguish these interpretations.

</details>

### Exercise 3

Apply the corrected-version control. What repairs the disagreement?

<details><summary>Answer 3</summary>

Using `v2` at both ends produces `[fail,pass,pass]` and `0` mismatches. No transported tag changes. Agreement is restored by selecting the shared codebook, not by changing the outcomes after decoding.

</details>

### Exercise 4

Can a hash of the tag sequence prove semantic compatibility?

<details><summary>Answer 4</summary>

No. Equal bytes can be interpreted by different mappings. A compatibility claim must retain the relevant codebook identity and its association with the message, not merely the payload hash.

</details>

### Exercise 5

How should an assistant report an unknown codebook version?

<details><summary>Answer 5</summary>

Retain the original tags and mark decoding unresolved. Do not choose a mapping because its verdict seems plausible. A future project change needs an explicit compatibility contract and real tests beyond this authored correspondence table.

</details>
