An agent shortens a handoff and claims that compression preserved everything because the file became smaller. The handoff prerequisite shows why a summary can merge states that require different decisions. This lesson compares that irreversible operation with an explicitly reversible encoding. Its byte counts come from a toy format, not a benchmark of a real compressor or a measured token-saving workflow.

The primary zlib specification describes a lossless compressed-data format. That motivates checking reversibility, but our run-length notation is a separate authored teaching format. Assume the input alphabet and decoder are known. Each run stores its symbol and a single count character, with the fixed header charged separately. The assumption excludes long runs and arbitrary binary input; extending the format would require another accounting rule.

For the repeated input, expand each encoded run and compare the result with the complete original string. A correct round trip checks byte identity for this input under the stated decoder. The stored size includes the header rather than treating it as free. A payload-only report would exaggerate the reduction. Conversely, a large header shared across many records would require an explicitly allocated cost rather than silently disappearing from the denominator.

The alternating negative control expands because every symbol needs its own run pair. Losslessness does not promise that every input gets smaller. The alphabet-only summary is shorter still, but different orders and counts map to it. It can answer which symbols appeared, yet it cannot reconstruct the original sequence or support an order-dependent decision. A better summary therefore depends on the receiver's actual question.

For the source-assisted task, read the prerequisite's handoff collision and the specification's lossless-format scope. Encode and decode both fixed strings by hand as the direct baseline. Then ask an assistant to distinguish byte equality, task sufficiency and stored size in a proposed handoff. Retain the expanding case and the lossy collision. Reject a proposal that labels every smaller representation lossless or claims a production compression ratio from this toy ledger.
