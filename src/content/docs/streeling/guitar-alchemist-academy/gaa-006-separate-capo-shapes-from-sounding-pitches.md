## The project question

A guitarist knows the chord the singer needs but wants a familiar shape with a capo. Another guitarist knows the shape and asks what the band will hear. These questions require opposite directions through the same relationship. GA's public [CapoSkill](https://github.com/GuitarAlchemist/ga/blob/dc2e74cbd992a298f67efb928b5b3754615e1924/Common/GA.Business.ML/Agents/Skills/CapoSkill.cs), pinned at `dc2e74cbd992a298f67efb928b5b3754615e1924`, explicitly distinguishes the two.

Use English letter names here, equal-tempered semitone arithmetic and an ordinary full capo. A partial capo, alternate tuning, fret limits and an actual fingering need additional information. [WML-005](../../world-music-languages/wml-005-declare-note-name-conventions/) explains why an unspecified B must be interpreted before any calculation.

## 1. Add to predict sound; subtract to choose a shape

With C as pitch class 0, sounding class is shape class plus capo fret, reduced modulo 12. To choose a shape for a requested sound, subtract the capo fret and reduce to a nonnegative class. The pinned skill validates frets from 0 through 12; this source constraint is distinct from the physical range of every guitar or every possible capo placement.

The [actual GA transposition probes](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/pitch-context-2026-10-22/theory-tool-probes.json) returned C# for B shifted up 2 and Gm for Bm shifted down 4. These are calls to the chord-transposition tool, with unknown service revision. They are not executions of the pinned CapoSkill or proof that an English or French prompt reaches it.

### Practice exercise 1: identify the direction

What sounds when a B major shape is played with capo 2? What minor shape produces sounding B minor with capo 4? Give the pitch-class calculations.

> **Answer:** B major shape gives C# major: `(11+2)%12 = 1`. Sounding B minor with capo 4 requires G minor: `(11-4)%12 = 7`. Addition predicts the sound from a shape; subtraction chooses the shape from the desired sound.

## 2. Preserve quality while moving the root

For this lesson, a major triad has relative semitone intervals 0, 4 and 7; a minor triad has 0, 3 and 7. Adding the same offset to every note preserves those relative intervals. The [fixed arithmetic packet](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/pitch-context-2026-10-22/capo-arithmetic.json) enumerates 12 starting classes, 13 capo positions and 2 qualities, giving 312 cases. Each recovers its starting class with the inverse operation and preserves its declared triad intervals.

This is a finite arithmetic check. It does not measure finger comfort, prove support for every chord-symbol extension or establish that a player produced the intended sound. In particular, replacing the G minor shape in the preceding exercise with G major changes the requested quality even though its root class is correct.

### Practice exercise 2: detect a quality error

For sounding B minor with capo 4, compare a G minor shape with a G major shape. Give each resulting relative interval list. Why is checking only the root insufficient?

> **Answer:** G minor preserves intervals 0, 3, 7 and produces B minor. G major preserves 0, 4, 7 and produces B major. Both reach root class 11; a root-only check misses the changed third and therefore the changed quality.

## 3. A pitch class does not retain an octave

Capo 12 returns the same pitch class. It does not return the same absolute pitch. The authored register control starts with open low E at MIDI 40 and adds 12 to obtain 52, E one octave higher. Both reduce to class 4. A capo answer expressed as a chord root is therefore insufficient when another agent needs a specific sounding note number.

GA's pinned [TabToPitchConverter](https://github.com/GuitarAlchemist/ga/blob/dc2e74cbd992a298f67efb928b5b3754615e1924/Common/GA.Business.ML/Tabs/TabToPitchConverter.cs) separately combines standard-tuning offsets with fret positions; the inspected conversion has no capo parameter. That source observation is not a new execution of the converter. Do not assume that the presence of capo arithmetic elsewhere means every tab path applies it.

### Practice exercise 3: keep the register

The control starts at 40 with capo 12. Give the resulting absolute number and both pitch classes. Can an answer of “E” alone show that the octave is correct?

> **Answer:** The absolute result is 52; both pitch classes are 4. “E” alone cannot distinguish 40 from 52. Keep the absolute note or register when the receiving task needs sounding pitch rather than only a chord root.

## 4. Separate normalization, transposition and spelling

For a declared German B, first normalize to English Bb, class 10. Capo 2 then yields class 0, C. For an English B, the same capo yields class 1, C#. The [language decision table](https://github.com/spareilleux/learn/blob/main/code/streeling/evidence/pitch-context-2026-10-22/language-decisions.json) preserves these inputs separately. Correct capo arithmetic cannot recover a naming convention discarded before it ran.

Enharmonic output spelling is another choice. C shape with capo 3 gives class 3, which can be named Eb or D# in this equal-tempered calculation. The pinned skill chooses a spelling preference from the input; a transposition tool's spelling need not establish how that skill would answer every natural-language phrase. Preserve musical context when notation matters rather than treating class equality as a universal spelling rule.

### Practice exercise 4: explain two different disagreements

Compare C versus C# after interpreting B under the two declared conventions with capo 2. Then compare Eb versus D# for C shape with capo 3. Are these the same kind of disagreement?

> **Answer:** No. C and C# have different classes, 0 and 1, because the source B was interpreted differently. Eb and D# share class 3 in the declared equal-tempered calculation but differ in spelling. Interpretation errors and enharmonic spelling choices require different explanations.

## 5. Compose operations only after declaring their domains

Suppose an authored written note has coordinate 64, an explicit instrument transposition of -1 octave, and a separately declared capo offset of 2 semitones that has not already been encoded. The calculation is `64-12+2 = 54`. This is a deliberately composed arithmetic fixture; it does not claim that a real score should always add a separate capo offset. A score or tab may already encode its sounding pitches. Inspect that policy before applying another adjustment.

[MCL-005](../../musicology/mcl-005-preserve-written-and-sounding-pitch/) shows how a parser can discard transposition metadata. A useful agent handoff states the naming convention, whether the target is a shape or sounding pitch, quality, capo position, register when needed, which adjustments are already applied and the evidence scope. This is a proposed checklist for the task, not a newly imposed repository schema.

### Practice exercise 5: avoid counting an offset twice

Calculate the declared composed control from 64, -1 octave and an unapplied capo 2. If an incoming value is already the final sounding 54, should an agent add 2 again? State the question it must resolve first.

> **Answer:** The control gives 54. Adding 2 to an already final sounding 54 would give 56 and double-count the capo. Establish whether the incoming pitch already includes the capo and instrument transposition, and whether the requested output describes shape, written pitch or sound.
