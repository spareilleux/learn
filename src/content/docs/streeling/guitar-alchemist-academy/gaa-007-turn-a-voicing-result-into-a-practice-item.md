## The project question

GA can propose a voicing. What must change before the result becomes a checkable practice question? The [pinned voicing skill](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Common/GA.Business.ML/Agents/Skills/ChordVoicingsSkill.cs#L130-L167) supplies displayed text and structured diagram, chord-name, instrument and retrieval-score fields. Those fields are useful material for a lesson; they are not a learner's answer, an answer-reveal policy or a measurement of learning.

[GAA-004](../../guitar-alchemist-academy/gaa-004-choose-a-useful-voicing/) compares voicing proposals with a guitarist's needs. Here we define the question and acceptance rule before scoring anything. All four candidate shapes below are authored fixtures, not captured results returned by GA.

## 1. Choose the target before hiding a field

Consider two different tasks. “Name the chord represented by this diagram” can display the diagram but must withhold the chord-name answer. “Give any C-major-triad shape under this tuning” can display the requested chord name but must not present the example shape as a memory answer. A third task, “reproduce the exact open-C shape just learned,” deliberately tests one previously specified shape.

The same chord-name field is an answer in the first task and an intended cue in the other two. A universal instruction to hide every label would remove useful task information. A practice item instead declares target, visible cues, accepted responses and reveal time. These are proposed lesson fields, not an implemented GA item API.

### Practice exercise 1: classify a visible cue

Should C major be visible when asking the learner to name an already labelled C-major diagram? Should it be visible when requesting any C-major-triad shape? What extra qualification makes an exact-shape question unambiguous?

> **Answer:** Withhold it when it is the answer to the naming task. Keep it as the requested target in the any-shape task. An exact-shape task must explicitly identify the previously learned shape and its string-order convention; “any C major” does not specify one fret array.

## 2. Build a key from declared coordinates

At commit `76efbffd5af82b46c3146957a6bd4504008eeb89`, the [diagram formatter](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Common/GA.Business.ML/Notation/PlayableNotationFormatter.cs#L30-L39) documents stored diagrams as high-string first and charts as low-string first. Its selected open-C example reverses raw `0-1-0-2-3-x` into chart `x-3-2-0-1-0`. The [checked-in reversal cases](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Tests/Common/GA.Business.ML.Tests/Notation/PlayableNotationFormatterTests.cs#L37-L42) include that pair. Reading assertions is not a fresh test run.

The skill formats its displayed result in chart order while its structured `diagram` field retains the raw value. A consumer must identify which representation it is reading. For the authored key, declare standard low-to-high MIDI tuning `[40,45,50,55,59,64]`, no capo, integer equal-tempered frets and muted `x` strings excluded. The chart's sounding MIDI notes are `[48,52,55,60,64]`, or C3, E3, G3, C4, E4 under C4 = 60. This arithmetic checks a proposed answer, not whether a player can execute it cleanly.

### Practice exercise 2: derive the sounding key

Reverse the raw example into chart order and calculate its sounding MIDI sequence under the declared tuning. Would treating the structured raw field as an already formatted chart preserve the same string assignment?

> **Answer:** The chart is `x-3-2-0-1-0`; adding frets to the unmuted open strings gives `[48,52,55,60,64]`. Treating the raw order as chart order would attach its tokens to different strings and would not preserve the assignment. Retain source revision, tuning, capo and order with the key.

## 3. Accept an answer according to the question

Use these authored low-to-high candidates. The restricted any-triad criterion requires all and only pitch classes C, E and G, each present at least once; it ignores register and doubling. It is not a universal definition of every acceptable C-labelled musical voicing.

| Candidate | Chart | Distinct pitch classes, C = 0 | Exact A | Restricted any C-major triad |
| --- | --- | --- | --- | --- |
| A | `x-3-2-0-1-0` | 0, 4, 7 | yes | yes |
| B | `x-3-5-5-5-3` | 0, 4, 7 | no | yes |
| C | `x-3-2-0-0-0` | 0, 4, 7, 11 | no | no |
| D | `x-3-2-0-1-x` | 0, 4, 7 | no | yes |

An exact-array validator would falsely reject B and D if the question promised any shape satisfying the declared triad criterion. A pitch-class-only validator would falsely accept B and D for the exact-A task. Candidate C adds B and fails this particular triad-only rule. A musical exercise permitting extensions would need another rule.

### Practice exercise 3: audit the acceptance rule

Which candidates pass the exact-A task and which pass the restricted any-triad task? Why is neither acceptance set a proof of physical playability or the only musically useful interpretation?

> **Answer:** Only A passes exact-A. A, B and D pass the restricted triad rule; C fails because pitch class 11 is extra. These are declared symbolic criteria. Fingering, sustain, muting, sound and a different harmonic brief require separate checks.

## 4. Do not turn retrieval confidence into recall probability

The selected skill assigns response confidence by clamping the top retrieval score between 0 and 1. For authored finite scores -0.2, 0.8 and 1.2, that operation gives 0, 0.8 and 1. It does not estimate whether a learner will remember a chord tomorrow. A bounded number and a probability about a defined learner event are different claims.

The [RAG query evaluation record](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Common/GA.Business.ML/Rag/RagEvaluationModels.cs#L3-L31) describes query partitions, result counts, retrieval scores and latency. It is not a retention outcome. Do not relabel either score when building a practice dashboard.

### Practice exercise 4: interpret a score

A result has retrieval score 0.8 and response confidence 0.8. May a lesson display “80% chance you will recall this tomorrow”? Give the two out-of-range clamping controls and the missing observation.

> **Answer:** No. Scores -0.2 and 1.2 clamp to 0 and 1, but clamping supplies no learner calibration. A defined delayed, unassisted response under a recorded cue and scoring protocol is missing, as is evidence relating predictions to that event.

## 5. Separate a plan from an attempt

The [practice routine types](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Common/GA.Business.DSL/Types/PracticeRoutineTypes.fs#L81-L101) name accuracy, tempo and other goals/tracking items. The [catalog practice skill](https://github.com/GuitarAlchemist/ga/blob/76efbffd5af82b46c3146957a6bd4504008eeb89/Common/GA.Business.ML/Agents/Skills/PracticeRoutineSkill.cs#L3-L16) supplies a structured-plan response. Neither inspected boundary supplies this lesson's actual answer-before-feedback observation. This is a statement about selected sources, not a repository-wide absence claim.

### Practice exercise 5: prepare a checkable item record

What must a future exercise retain beyond the returned voicing and its score? What additional evidence is needed before calling a completed item a learning benefit?

> **Answer:** Retain source/query identity, raw and displayed order, instrument/tuning/capo, target, permitted cues, verified key, acceptance rule, answer before reveal, assistance, attempt identity and timing. Record an actual delayed assessment before claiming retention, and use a justified comparison before attributing benefit. A plan, a click or a score alone supplies neither result.
