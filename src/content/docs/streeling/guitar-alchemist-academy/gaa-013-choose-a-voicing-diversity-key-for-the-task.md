A GA answer can list several chord shapes while a summary says that all are duplicates. Both statements can be true under different equivalence rules. A guitarist seeking alternative registers needs a different view from someone counting chord pitch-class families. This lesson makes the diversity key explicit before an agent compresses results. It adds a representation decision to the prerequisite's selection task, without modifying embeddings, search code or the fixed musical schema.

## Read the retained evidence

Read the retained practice candidates: several shapes share the same pitch-class family while differing in exact notes and acceptance under an exact-shape task. That source supplies the project problem, not the candidate list below. Our new lists are authored sounding-note examples. No live retrieval supplied them, and deduplication by pitch class must not be presented as the implementation policy of a search service.

### Exercise 1

Use candidates `[[48,52,55,60],[48,55,60,64],[52,55,60,64],[48,52,55,60]]`. All are ascending lists. A pitch-class key takes each value modulo `12`, removes duplicates and sorts the result. This discards register, multiplicity and bass ordering deliberately. It is useful only when the task asks about that projected family.

How many distinct pitch-class sets appear?

<details><summary>Answer 1</summary>

There is `1`, with key `[0,4,7]`. This equality does not imply that the sounding-note lists, bass notes or fingerings are identical.

</details>

### Exercise 2

An absolute voicing key retains the entire ordered note list. The last candidate repeats the first exactly, while the middle candidates differ. Under this key there are `3` distinct voicings. An agent claiming result diversity should name its key rather than quoting the number alone, because the same supplied data supports different counts.

How many distinct absolute voicings remain?

<details><summary>Answer 2</summary>

There are `3`. The exact repeated first/last list collapses, but register and multiplicity remain part of this key.

</details>

### Exercise 3

A bass-class key uses the lowest sounding note modulo `12`. The first, second and last candidates have bass class `0`; the third has `4`. Thus there are `2` bass classes despite only one pitch-class family. A task about inversion can retain this information without pretending to assess physical fingering or voice continuity.

What does the bass key preserve that the family key loses?

<details><summary>Answer 3</summary>

It distinguishes bass classes `0` and `4`, giving `2` classes. The family set `[0,4,7]` alone cannot identify which member is lowest.

</details>

### Exercise 4

The negative control changes the third candidate to `[52,55,60,65]`. Its family becomes `[0,4,5,7]`. There are now `2` pitch-class sets, while absolute-voicing count stays `3` and bass-class count stays `2`. Checking only the unchanged counts would miss a changed musical family, so a review should retain keys as well as totals.

Which diversity result changes in the control?

<details><summary>Answer 4</summary>

Pitch-class families increase to `2`, namely `[[0,4,7],[0,4,5,7]]`. Distinct voicings remain `3` and bass classes `2`. One changed coordinate affects the keys differently.

</details>

### Exercise 5

For a practice suggestion, a player may want an inversion, a nearby hand position or a different timbre. None is supplied by an abstract family count alone. Keep candidates accessible after summarization and explain the information removed by the selected key. A future similarity method can be assessed against this manual baseline before adopting a new abstraction.

What would falsify a summary claiming to preserve register diversity?

<details><summary>Answer 5</summary>

Collapsing all main-case candidates into one record with no retained voicing distinctions loses the requested register information. A correct family count would not rescue that stronger preservation claim.

</details>
