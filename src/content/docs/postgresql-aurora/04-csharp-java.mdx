## Connecting

In .NET, an [`NpgsqlDataSource`](https://www.npgsql.org/doc/basic-usage.html) holds a connection string and its pool. An application creates one per database and keeps it, often as a singleton in dependency injection; `NpgsqlConnection` objects come from it ([`Db.cs`, lines 8-13](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/Db.cs#L8-L13), [`L04.cs`, lines 10-21](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L10-L21)):

```csharp
    public static string ConnectionString =>
        Environment.GetEnvironmentVariable("PG_CONNECTION")
        ?? "Host=localhost;Port=5432;Username=postgres;Password=learn;Database=learn;Application Name=learn-csharp";

    public static NpgsqlDataSource DataSource(string? extra = null) =>
        NpgsqlDataSource.Create(extra is null ? ConnectionString : $"{ConnectionString};{extra}");

    public static async Task Connect()
    {
        // One NpgsqlDataSource per database for the whole application: it owns the connection pool
        await using var dataSource = Db.DataSource();
        await using var command = dataSource.CreateCommand(
            "SELECT current_user, current_setting('server_version'), (SELECT count(*) FROM ci.runs)");
        await using var reader = await command.ExecuteReaderAsync();
        await reader.ReadAsync();
        Console.WriteLine($"user: {reader.GetString(0)}");
        Console.WriteLine($"server: {reader.GetString(1)}");
        Console.WriteLine($"runs: {reader.GetInt64(2)}");
    }
```

```text
user: postgres
server: 18.6 (Debian 18.6-1.pgdg13+2)
runs: 125
```

In Java, [`DriverManager`](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/DriverManager.html) opens a new connection at each call, from a URL ([`L04.java`, lines 35-49](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L35-L49)):

```java
    static void connect() throws SQLException {
        try (Connection connection = DriverManager.getConnection(url());
             Statement statement = connection.createStatement();
             ResultSet rs = statement.executeQuery(
                     "SELECT current_user, current_setting('server_version'), (SELECT count(*) FROM ci.runs),"
                             + " current_setting('TimeZone')")) {
            rs.next();
            System.out.println("driver: " + connection.getMetaData().getDriverVersion());
            // The driver sets the session's TimeZone to the JVM's default time zone
            System.out.println("JVM time zone: " + java.util.TimeZone.getDefault().getID() + ", session TimeZone: " + rs.getString(4));
            System.out.println("user: " + rs.getString(1));
            System.out.println("server: " + rs.getString(2));
            System.out.println("runs: " + rs.getLong(3));
        }
    }
```

```text
driver: 42.7.13
JVM time zone: America/Toronto, session TimeZone: America/Toronto
user: postgres
server: 18.6 (Debian 18.6-1.pgdg13+2)
runs: 125
```

The second line is the first difference between the drivers. **pgjdbc sets the session's `TimeZone` to the JVM's default time zone**: it sends it in the connection's startup message, next to `DateStyle` ([`ConnectionFactoryImpl.java`, lines 458-464](https://github.com/pgjdbc/pgjdbc/blob/3297557c6a8059d0d6e3522c79f0bd9a6f82ee07/pgjdbc/src/main/java/org/postgresql/core/v3/ConnectionFactoryImpl.java#L458-L464)). Every `timestamptz` the server formats as text for this connection is in that zone. `check.sh` fixes the JVM's zone with `-Duser.timezone=America/Toronto`, so that the output is the same on every machine; exercise 2 changes it. Npgsql doesn't send the client's zone: the session keeps the server's default, UTC in the image, unless the connection string sets `Timezone`.

`Application Name` and `ApplicationName` name the connection in [`pg_stat_activity`](https://www.postgresql.org/docs/18/monitoring-stats.html#MONITORING-PG-STAT-ACTIVITY-VIEW): the pool examples below count their own sessions with it.

## Parameters

PostgreSQL's own placeholders are positional: `$1`, `$2`. Npgsql accepts them as they are, and also `@name`, which it rewrites to `$1` before sending the query. JDBC uses `?`, which pgjdbc rewrites to `$1` ([`L04.cs`, lines 27-53](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L27-L53), [`L04.java`, lines 53-67](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L53-L67)):

```csharp
        // Positional parameters: $1, $2 are what PostgreSQL itself understands
        await using (var command = dataSource.CreateCommand("""
            SELECT run_id, started_at FROM ci.runs
            WHERE workflow_name = $1 AND started_at >= $2
            ORDER BY started_at, run_id
            LIMIT 2
            """))
        {
            command.Parameters.Add(new() { Value = "Rust course examples" });
            command.Parameters.Add(new() { Value = new DateTime(2026, 9, 13, 18, 0, 0, DateTimeKind.Utc) });
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                var startedAt = reader.GetDateTime(1);
                Console.WriteLine($"{reader.GetInt64(0)} {startedAt:O} Kind={startedAt.Kind}");
            }
        }

        // Named parameters: Npgsql rewrites @os into $1 before sending the query
        await using (var command = dataSource.CreateCommand("""
            SELECT count(*) FROM ci.jobs WHERE labels[1] = @os AND duration > @longer_than
            """))
        {
            command.Parameters.AddWithValue("os", "windows-latest");
            command.Parameters.AddWithValue("longer_than", TimeSpan.FromMinutes(2));
            Console.WriteLine($"windows jobs over 2 minutes: {await command.ExecuteScalarAsync()}");
        }
```

```text
34776807003 2026-09-13T19:09:08.0000000Z Kind=Utc
34777004019 2026-09-13T19:12:56.0000000Z Kind=Utc
windows jobs over 2 minutes: 8
```

```java
            // JDBC's ? placeholders; the driver sends them as $1, $2
            try (PreparedStatement ps = connection.prepareStatement("""
                    SELECT run_id, started_at FROM ci.runs
                    WHERE workflow_name = ? AND started_at >= ?
                    ORDER BY started_at, run_id
                    LIMIT 2
                    """)) {
                ps.setString(1, "Rust course examples");
                ps.setObject(2, OffsetDateTime.of(2026, 9, 13, 18, 0, 0, 0, ZoneOffset.UTC));
                try (ResultSet rs = ps.executeQuery()) {
                    while (rs.next()) {
                        System.out.println(rs.getLong(1) + " " + rs.getObject(2, OffsetDateTime.class));
                    }
                }
            }
```

```text
34776807003 2026-09-13T19:09:08Z
34777004019 2026-09-13T19:12:56Z
```

The values travel apart from the SQL text, in the protocol's `Bind` message: no SQL injection, and no quoting to get wrong. `TimeSpan` maps to `interval`, and the named parameter `@longer_than` is compared with the virtual column `duration` of lesson 2.

### Lists: an array, not IN

`WHERE x IN (@a, @b, @c)` needs one parameter per value, and a different statement for each list length. PostgreSQL takes the whole list as one array parameter ([`L04.cs`, lines 55-66](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L55-L66), [`L04.java`, lines 69-78](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L69-L78)):

```csharp
        // An array parameter replaces a list of values: = ANY ($1), not IN (...)
        await using (var command = dataSource.CreateCommand("""
            SELECT labels[1], count(*) FROM ci.jobs WHERE labels[1] = ANY ($1) GROUP BY 1 ORDER BY 1
            """))
        {
            command.Parameters.Add(new() { Value = new[] { "macos-latest", "windows-latest" } });
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                Console.WriteLine($"{reader.GetString(0)}: {reader.GetInt64(1)}");
            }
        }
```

```java
            // An array parameter: = ANY (?)
            try (PreparedStatement ps = connection.prepareStatement(
                    "SELECT labels[1], count(*) FROM ci.jobs WHERE labels[1] = ANY (?) GROUP BY 1 ORDER BY 1")) {
                ps.setArray(1, connection.createArrayOf("text", new String[] {"macos-latest", "windows-latest"}));
                try (ResultSet rs = ps.executeQuery()) {
                    while (rs.next()) {
                        System.out.println(rs.getString(1) + ": " + rs.getLong(2));
                    }
                }
            }
```

```text
macos-latest: 34
windows-latest: 35
```

Npgsql maps a `string[]` to `text[]`; in JDBC, `Connection.createArrayOf` builds the array. SQL Server's equivalents are a table-valued parameter or `STRING_SPLIT`.

### DateTime, DateTimeOffset and time zones

Npgsql decides the PostgreSQL type of a [`DateTime`](https://learn.microsoft.com/dotnet/api/system.datetime) from its `Kind`, as its [date and time documentation](https://www.npgsql.org/doc/types/datetime.html) describes: `Utc` is sent as `timestamptz`, `Unspecified` and `Local` as `timestamp` without time zone. Compared with a `timestamptz` column, a `timestamp` is converted by the server, **in the session's time zone** ([`L04.cs`, lines 68-94](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L68-L94)):

```csharp
        // DateTime.Kind decides the parameter's type: Utc is sent as timestamptz, Unspecified and Local as timestamp,
        // which the server converts to timestamptz in the session's time zone
        foreach (var options in new[] { "Timezone=UTC", "Timezone=America/Toronto" })
        {
            await using var zoned = Db.DataSource(options);
            foreach (var kind in new[] { DateTimeKind.Utc, DateTimeKind.Unspecified })
            {
                await using var command = zoned.CreateCommand("SELECT count(*) FROM ci.runs WHERE started_at >= $1");
                command.Parameters.Add(new() { Value = new DateTime(2026, 9, 14, 0, 0, 0, kind) });
                Console.WriteLine($"{options}, Kind={kind}: {await command.ExecuteScalarAsync()} runs since 2026-09-14 00:00");
            }
        }
        await using (var command = dataSource.CreateCommand("SELECT count(*) FROM ci.runs WHERE started_at >= $1"))
        {
            var toronto = new DateTimeOffset(2026, 9, 14, 0, 0, 0, TimeSpan.FromHours(-4));
            command.Parameters.Add(new() { Value = toronto });
            try
            {
                await command.ExecuteScalarAsync();
            }
            catch (ArgumentException e)
            {
                Console.WriteLine($"{e.GetType().Name}: {e.Message}");
            }
            command.Parameters[0].Value = toronto.ToUniversalTime();
            Console.WriteLine($"DateTimeOffset in UTC: {await command.ExecuteScalarAsync()} runs since 2026-09-14 00:00 in Toronto");
        }
```

```text
Timezone=UTC, Kind=Utc: 82 runs since 2026-09-14 00:00
Timezone=UTC, Kind=Unspecified: 82 runs since 2026-09-14 00:00
Timezone=America/Toronto, Kind=Utc: 82 runs since 2026-09-14 00:00
Timezone=America/Toronto, Kind=Unspecified: 59 runs since 2026-09-14 00:00
ArgumentException: Cannot write DateTimeOffset with Offset=-04:00:00 to PostgreSQL type 'timestamp with time zone', only offset 0 (UTC) is supported.  (Parameter 'value')
DateTimeOffset in UTC: 59 runs since 2026-09-14 00:00 in Toronto
```

- The same `DateTime`, midnight on September 14, counts 82 runs in three cases, and 59 when it is `Unspecified` and the session is in Toronto: midnight in Toronto is 04:00 UTC, and 23 runs started in between. Exercise 2 of lesson 2 found the same 23 runs.
- The query is correct in the four cases. The count depends on a `Kind` that comes from wherever the `DateTime` was created, and on a session setting. Send `Kind=Utc` values to `timestamptz` columns.
- A [`DateTimeOffset`](https://learn.microsoft.com/dotnet/api/system.datetimeoffset) with a non-zero offset is refused before anything is sent: `timestamptz` doesn't store an offset (lesson 2), and Npgsql won't drop one silently. Convert with `ToUniversalTime()`.

In Java, [`OffsetDateTime`](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/time/OffsetDateTime.html) keeps its offset on the way to the server, and the server compares instants ([`L04.java`, lines 80-87](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L80-L87)):

```java
            // An OffsetDateTime keeps its offset; the server compares instants
            try (PreparedStatement ps = connection.prepareStatement("SELECT count(*) FROM ci.runs WHERE started_at >= ?")) {
                ps.setObject(1, OffsetDateTime.of(2026, 9, 14, 0, 0, 0, 0, ZoneOffset.ofHours(-4)));
                try (ResultSet rs = ps.executeQuery()) {
                    rs.next();
                    System.out.println("runs since 2026-09-14 00:00 in Toronto: " + rs.getLong(1));
                }
            }
```

```text
runs since 2026-09-14 00:00 in Toronto: 59
```

Reading, `reader.GetDateTime` returns a `DateTime` with `Kind=Utc`, and `rs.getObject(2, OffsetDateTime.class)` an `OffsetDateTime` in UTC, whatever the session's zone: the first lines of both outputs above. Only a value formatted as text by the server, such as `rs.getString`, follows the session's `TimeZone`.

### Parameter types

A parameter has a type, and PostgreSQL doesn't convert a string to a number silently ([`L04.cs`, lines 96-108](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L96-L108), [`L04.java`, lines 89-95](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L89-L95)):

```csharp
        // A value that doesn't match the column's type is PostgreSQL's error, not Npgsql's
        await using (var command = dataSource.CreateCommand("SELECT count(*) FROM ci.runs WHERE run_id = $1"))
        {
            command.Parameters.Add(new() { Value = "34852867099" });
            try
            {
                await command.ExecuteScalarAsync();
            }
            catch (PostgresException e)
            {
                Console.WriteLine($"{e.SqlState}: {e.MessageText}");
            }
        }
```

```text
42883: operator does not exist: bigint = text
```

```java
            // setString binds a varchar: PostgreSQL has no bigint = varchar operator
            try (PreparedStatement ps = connection.prepareStatement("SELECT count(*) FROM ci.runs WHERE run_id = ?")) {
                ps.setString(1, "34852867099");
                ps.executeQuery();
            } catch (PSQLException e) {
                System.out.println(e.getSQLState() + ": " + e.getServerErrorMessage().getMessage());
            }
```

```text
42883: operator does not exist: bigint = character varying
```

Npgsql sends a `string` as `text`, pgjdbc sends `setString` as `varchar`, and neither type has an `=` operator with `bigint`. SQL Server would convert the string implicitly. The fix is the right .NET or Java type; pgjdbc's [`stringtype=unspecified`](https://jdbc.postgresql.org/documentation/use/) property sends strings untyped and lets the server infer the type, which also hides mistakes. Error `42883` is `undefined_function` in the [list of error codes](https://www.postgresql.org/docs/18/errcodes-appendix.html): an operator is a function.

## Pools

Opening a PostgreSQL connection starts a **server process**, lesson 1's "one process per connection": a TCP connection, authentication, a fork. A pool keeps connections open and hands them out again ([`L04.cs`, lines 111-153](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L111-L153)):

```csharp
    public static async Task Pool()
    {
        foreach (var pooling in new[] { true, false })
        {
            await using var dataSource = Db.DataSource($"Pooling={pooling}");
            var backends = new HashSet<int>();
            for (var i = 0; i < 20; i++)
            {
                await using var connection = await dataSource.OpenConnectionAsync();
                backends.Add(connection.ProcessID);
            }
            Console.WriteLine($"Pooling={pooling}: 20 opens, {backends.Count} server process(es)");
        }

        // Five connections held at the same time are five server processes
        await using (var dataSource = Db.DataSource("Application Name=learn-pool"))
        {
            var connections = new List<NpgsqlConnection>();
            for (var i = 0; i < 5; i++)
            {
                connections.Add(await dataSource.OpenConnectionAsync());
            }
            foreach (var connection in connections)
            {
                await connection.CloseAsync();
            }
            await using var command = dataSource.CreateCommand("""
                SELECT state, count(*) FROM pg_stat_activity
                WHERE application_name = 'learn-pool' GROUP BY state ORDER BY state
                """);
            await using var reader = await command.ExecuteReaderAsync();
            while (await reader.ReadAsync())
            {
                Console.WriteLine($"after closing: {reader.GetInt64(1)} {reader.GetString(0)}");
            }
        }
        await using (var dataSource = Db.DataSource())
        {
            await using var command = dataSource.CreateCommand(
                "SELECT count(*) FROM pg_stat_activity WHERE application_name = 'learn-pool'");
            Console.WriteLine($"after disposing the data source: {await command.ExecuteScalarAsync()}");
        }
    }
```

```text
Pooling=True: 20 opens, 1 server process(es)
Pooling=False: 20 opens, 20 server process(es)
after closing: 1 active
after closing: 4 idle
after disposing the data source: 0
```

- With pooling, 20 opens and closes use one server process; without, 20.
- Five connections held at the same time are five processes. Closed, they stay open on the server, `idle`, in the pool. The one `active` session is the connection running the `pg_stat_activity` query itself.
- Disposing the data source closes its connections.

Npgsql's pool is on by default, per data source, with at most 100 connections (`Maximum Pool Size`) and a minimum of 0; idle connections above the minimum are closed after 300 seconds ([connection string parameters](https://www.npgsql.org/doc/connection-string-parameters.html)). SqlClient has the same defaults of 100 and 0.

pgjdbc has no pool of its own: each `DriverManager.getConnection` is a new process. HikariCP is the usual pool ([`L04.java`, lines 107-142](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L107-L142)):

```java
    static void pool() throws SQLException {
        Set<Integer> backends = new HashSet<>();
        for (int i = 0; i < 20; i++) {
            try (Connection connection = DriverManager.getConnection(url())) {
                backends.add(backendPid(connection));
            }
        }
        System.out.println("DriverManager: 20 connections, " + backends.size() + " server process(es)");

        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(url().replace("learn-java", "learn-hikari"));
        config.setMaximumPoolSize(5);
        try (HikariDataSource pool = new HikariDataSource(config)) {
            backends.clear();
            for (int i = 0; i < 20; i++) {
                try (Connection connection = pool.getConnection()) {
                    backends.add(backendPid(connection));
                }
            }
            System.out.println("HikariCP: 20 connections, " + backends.size() + " server process(es)");
            // HikariCP opens connections in the background until minimumIdle, which defaults to maximumPoolSize
            try (Connection connection = pool.getConnection()) {
                long deadline = System.currentTimeMillis() + 10_000;
                long sessions;
                do {
                    try (Statement statement = connection.createStatement();
                         ResultSet rs = statement.executeQuery(
                                 "SELECT count(*) FROM pg_stat_activity WHERE application_name = 'learn-hikari'")) {
                        rs.next();
                        sessions = rs.getLong(1);
                    }
                } while (sessions < 5 && System.currentTimeMillis() < deadline && sleep(100));
                System.out.println("sessions opened by the pool: " + sessions);
            }
        }
    }
```

```text
DriverManager: 20 connections, 20 server process(es)
HikariCP: 20 connections, 1 server process(es)
sessions opened by the pool: 5
```

HikariCP's `minimumIdle` defaults to `maximumPoolSize`, per its [README](https://github.com/brettwooldridge/HikariCP): a pool of 5 opens 5 sessions in the background as soon as it starts, used or not. Npgsql opens connections on demand.

### A pool meets max_connections

The server has a limit too, [`max_connections`](https://www.postgresql.org/docs/18/runtime-config-connection.html#GUC-MAX-CONNECTIONS), 100 by default ([`L04.cs`, lines 308-331](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L308-L331)):

```csharp
    public static async Task TooMany()
    {
        // No pool: each Open is a new server process, until max_connections (100 by default) is reached
        await using var dataSource = Db.DataSource("Pooling=false");
        var connections = new List<NpgsqlConnection>();
        try
        {
            for (var i = 0; i < 200; i++)
            {
                connections.Add(await dataSource.OpenConnectionAsync());
            }
        }
        catch (PostgresException e)
        {
            Console.WriteLine($"{e.SqlState}: {e.MessageText}");
        }
        finally
        {
            foreach (var connection in connections)
            {
                await connection.DisposeAsync();
            }
        }
    }
```

```text
53300: sorry, too many clients already
```

Npgsql's default maximum pool size is the server's default maximum of connections. One application instance at full load can take them all; two instances with default settings can ask for 200. Size the pools from the server's limit: the sum over every application instance, plus the administrators, must stay below it. Connections are expensive processes, and a few dozen well-used connections usually beat hundreds of idle ones.

## Prepared statements

A prepared statement is parsed and planned once, then executed with new parameters. Both drivers prepare on the server only after a statement has been executed a few times ([`L04.cs`, lines 155-170](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L155-L170), [`L04.java`, lines 154-171](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L154-L171)):

```csharp
    public static async Task Prepare()
    {
        // Npgsql prepares a statement only when asked, or after Auto Prepare Min Usages executions (default 5)
        // when Max Auto Prepare is above 0
        await using var dataSource = Db.DataSource("Max Auto Prepare=10");

            await using var command = new NpgsqlCommand("SELECT count(*) FROM ci.jobs WHERE run_id = $1", connection);
            command.Parameters.Add(new() { Value = 34852867099L });
```

```java

        // The driver switches to a named server-side prepared statement on the prepareThreshold-th execution (default 5)
        try (Connection connection = DriverManager.getConnection(url());
             PreparedStatement count = connection.prepareStatement(
                     "SELECT count(*) FROM pg_prepared_statements WHERE statement ~ 'ci\\.jobs WHERE'")) {

                    ps.setLong(1, 34852867099L);
                    ps.executeQuery().close();
                }
                try (ResultSet rs = count.executeQuery()) {
                    rs.next();
                    System.out.println("after " + i + " execution(s): " + rs.getLong(1) + " prepared statement(s)");
```

- **Npgsql** doesn't prepare automatically unless `Max Auto Prepare` is above 0; its default is 0. Then a statement executed `Auto Prepare Min Usages` times, 5 by default, is prepared. `NpgsqlCommand.Prepare()` prepares explicitly.
- **pgjdbc** switches a `PreparedStatement` to a named server-side statement at the `prepareThreshold`-th execution, 5 by default ([connection properties](https://jdbc.postgresql.org/documentation/use/)). The counting query sets its own threshold to 0, so that it's never prepared and doesn't count itself.

A prepared statement belongs to one session, and a pooled connection keeps it across opens: that's why the pools matter here. Lesson 5 comes back to generic and custom plans.

## Bulk loads: COPY and batches

Lesson 1 loaded files with `COPY … FROM` a path **on the server**. From a program, `COPY … FROM STDIN` sends the rows over the connection. Npgsql writes them in PostgreSQL's binary format, typed ([`L04.cs`, lines 172-208](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/csharp/L04.cs#L172-L208)):

```csharp
    static IEnumerable<string[]> PackageRefs() =>
        File.ReadLines("../ladybugdb/data/ga/package_refs.csv").Skip(1).Select(line => line.Split(','));

    public static async Task Copy()
    {
        await using var dataSource = Db.DataSource();
        await using var connection = await dataSource.OpenConnectionAsync();
        await using (var create = new NpgsqlCommand("""
            DROP TABLE IF EXISTS ga.package_refs_import;
            CREATE TABLE ga.package_refs_import (LIKE ga.package_refs INCLUDING ALL);
            """, connection))
        {
            await create.ExecuteNonQueryAsync();
        }

        // COPY ... FROM STDIN in binary format: the client sends the rows, typed, in one stream
        await using (var writer = await connection.BeginBinaryImportAsync(

        {
            foreach (var fields in PackageRefs())

                await writer.WriteAsync(fields[0], NpgsqlDbType.Text);
                await writer.WriteAsync(fields[1], NpgsqlDbType.Text);
                await writer.WriteAsync(fields[2], NpgsqlDbType.Text);
            }
            Console.WriteLine($"copied: {await writer.CompleteAsync()} rows");

                   (SELECT count(*) FROM (TABLE ga.package_refs_import EXCEPT TABLE ga.package_refs) AS d)
            """, connection);
        await using var reader = await compare.ExecuteReaderAsync();
        await reader.ReadAsync();
        Console.WriteLine($"rows only in the server-side load: {reader.GetInt64(0)}, only in the client copy: {reader.GetInt64(1)}");
```

## Generated keys

`RETURNING` (lesson 3) gives back what the server generated. JDBC's portable API for it is [`Statement.RETURN_GENERATED_KEYS`](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/Connection.html#prepareStatement(java.lang.String,int)) ([`L04.java`, lines 199-241](https://github.com/spareilleux/learn/blob/15c2294/code/postgresql-aurora/java/src/main/java/dev/learn/pg/L04.java#L199-L241)):

```java
    static void generatedKeys() throws SQLException {
        try (Connection connection = DriverManager.getConnection(url())) {
            try (Statement statement = connection.createStatement()) {
                statement.execute("""
                        DROP TABLE IF EXISTS ci.notes;
                        CREATE TABLE ci.notes (
                            note_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
                            run_id  bigint NOT NULL REFERENCES ci.runs,
                            body    text NOT NULL,
                            created timestamptz NOT NULL DEFAULT '2026-09-15 00:00:00+00'
                        );
                        """);
            }
            // RETURN_GENERATED_KEYS: the driver appends RETURNING * to the INSERT
            try (PreparedStatement ps = connection.prepareStatement(
                    "INSERT INTO ci.notes (run_id, body) VALUES (?, ?)", Statement.RETURN_GENERATED_KEYS)) {
                ps.setLong(1, 34852867099L);
                ps.setString(2, "first deployment of the day");
                ps.executeUpdate();
                try (ResultSet keys = ps.getGeneratedKeys()) {
                    keys.next();
                    int columns = keys.getMetaData().getColumnCount();
                    StringBuilder line = new StringBuilder("generated keys:");
                    for (int c = 1; c <= columns; c++) {
                        line.append(' ').append(keys.getMetaData().getColumnName(c)).append('=').append(keys.getString(c));
                    }
                    System.out.println(line);
                }
            }
            // Naming the columns asks for RETURNING note_id only
            try (PreparedStatement ps = connection.prepareStatement(
                    "INSERT INTO ci.notes (run_id, body) VALUES (?, ?)", new String[] {"note_id"})) {
                ps.setLong(1, 34852867099L);
                ps.setString(2, "second note");
                ps.executeUpdate();
                try (ResultSet keys = ps.getGeneratedKeys()) {
                    keys.next();
                    System.out.println("generated keys: " + keys.getMetaData().getColumnCount() + " column, note_id="
                            + keys.getLong("note_id"));
                }
            }
        }
    }
```

## Errors

A server error arrives as [`PostgresException`](https://www.npgsql.org/doc/api/Npgsql.PostgresException.html) in Npgsql, and `PSQLException` in pgjdbc, with the five-character `SqlState` of the [error codes appendix](https://www.postgresql.org/docs/18/errcodes-appendix.html). Test the code, not the message: `23505` is `unique_violation` in every language, while the message follows `lc_messages`. Npgsql also defines constants such as `PostgresErrorCodes.UniqueViolation`.

The `DETAIL` of an error can contain data, as in lesson 2's "Failing row contains …". Npgsql redacts it unless the connection string sets `Include Error Detail=true`; exercise 1 shows both.

## On Aurora

*To verify: nothing in this section ran on AWS.* Npgsql and pgjdbc connect to Aurora PostgreSQL as to any PostgreSQL server. What changes is around the connection.

**TLS is required by default.** The [Aurora PostgreSQL security page](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraPostgreSQL.Security.html) gives the default of `rds.force_ssl` as 1 (on) for Aurora PostgreSQL 17 and later, and 0 for 16 and older; a connection without TLS is refused with `no pg_hba.conf entry for host …, SSL off`. The local container has `ssl` off. Both drivers default to `prefer`, which uses TLS when the server offers it but doesn't verify the certificate. Against Aurora, use `SSL Mode=VerifyFull` in Npgsql and `sslmode=verify-full` in pgjdbc, with the RDS certificate authority bundle as the trusted root.

**Passwords or IAM tokens.** With [IAM database authentication](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/UsingWithRDS.IAMDBAuth.html), the password is a token generated by the AWS SDK from IAM credentials. AWS gives it "a lifetime of 15 minutes", notes that it "doesn't affect the session after it is established", and that its size "is generally about 1 KB but can be larger". A pool opens new connections all day, so the token must be refreshed:

- In .NET, [`NpgsqlDataSourceBuilder.UsePeriodicPasswordProvider`](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/NpgsqlDataSourceBuilder.cs#L344-L371) calls a function on a timer, "the recommended way to fetch a rotating access token" according to its documentation comment; the function would call the AWS SDK for .NET's `RDSAuthTokenGenerator`.
- In Java, AWS documents the IAM authentication plugin of the [AWS Advanced JDBC Wrapper](https://github.com/aws/aws-advanced-jdbc-wrapper), which wraps pgjdbc.

**max_connections depends on the instance.** Its default on Aurora PostgreSQL is `LEAST({DBInstanceClassMemory/9531392},5000)`, per [performance and scaling for Aurora PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraPostgreSQL.Managing.html), which also recommends keeping "at least 3 more connections to support AWS automation". The `53300` of the pool section happens at whatever that number is; the arithmetic of pool sizes is the same.

**RDS Proxy and pinning.** [RDS Proxy](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-proxy.html) shares database connections between client connections at transaction boundaries. A client connection whose session state changed is **pinned** to its database connection until it disconnects. AWS's [list of pinning conditions for PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-proxy-pinning.html#rds-proxy-pinning.postgres) meets this lesson's drivers in three places:

- "Using `SET` commands" pins. A session setting such as the time zone belongs in the connection string (`Timezone`, or the JVM's zone for pgjdbc, sent at startup), or in the proxy's initialization query. Whether RDS Proxy pins on parameters sent in the startup message is *to verify*.
- "Using `PREPARE`, `DISCARD`, `DEALLOCATE`, or `EXECUTE` commands to manage prepared statements" pins. The drivers' automatic preparation uses the protocol's messages, not these SQL commands; the page doesn't say whether that pins, so it's *to verify*.
- "If you use connection pooling libraries with `DISCARD ALL` query configured as a reset query, RDS Proxy pins your client connection on release." Npgsql resets a pooled connection with `DISCARD ALL` when it goes back to the pool, unless it has prepared statements ([`NpgsqlConnector.cs`, lines 2752-2766](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/Internal/NpgsqlConnector.cs#L2752-L2766)). `No Reset On Close=true` turns the reset off, "at the cost of leaking state". Behind RDS Proxy, a pool in the application and a pool in the proxy are two layers doing the same job.

**Writer and readers.** Lesson 3 described the cluster endpoint and the reader endpoint. A program can hold one data source per endpoint, or give both hosts to one data source and let the driver pick by role: exercise 3 tries it on the local server. For fast failover in Java, AWS maintains the AWS Advanced JDBC Wrapper, which follows the cluster's topology instead of relying on DNS.

## Key takeaways

- One `NpgsqlDataSource` per database, kept for the application's lifetime; in Java, a HikariCP pool around pgjdbc.
- Use the parameters' real types. A string compared with a `bigint` is error `42883`, not a conversion.
- Send `DateTime` values with `Kind=Utc` to `timestamptz`; convert `DateTimeOffset` to UTC. pgjdbc sets the session's time zone from the JVM.
- `Maximum Pool Size` defaults to 100 and `max_connections` to 100: size pools from the server's limit.
- Both drivers prepare statements on the server after 5 executions, Npgsql only when `Max Auto Prepare` is set.
- `COPY FROM STDIN` and batches load rows in one round trip; one `INSERT` per row pays one round trip per row.
- The EF Core provider maps arrays natively; value converters written for SQLite lose information and hide `DateTime.Kind` problems.
- On Aurora: TLS required from version 17, IAM tokens valid 15 minutes, `max_connections` from the instance's memory, and a `DISCARD ALL` reset that pins RDS Proxy connections.

```java
    static void target() {
        // targetServerType: before handing out a connection, the driver checks the server's role, as it would for each
        // host of an Aurora cluster; the local server is a primary
        for (String target : List.of("primary", "preferSecondary", "secondary")) {
            try (Connection connection = DriverManager.getConnection(url() + "&targetServerType=" + target);
                 Statement statement = connection.createStatement();
                 ResultSet rs = statement.executeQuery("SELECT pg_is_in_recovery()")) {
                rs.next();
                System.out.println(target + ": connected, pg_is_in_recovery() = " + rs.getBoolean(1));
            } catch (SQLException e) {
                System.out.println(target + ": " + e.getSQLState() + ": " + e.getMessage());
            }
        }
    }
```

```text
primary: connected, pg_is_in_recovery() = false
preferSecondary: connected, pg_is_in_recovery() = false
secondary: 08001: Could not find a server with specified targetServerType: secondary
```

- Npgsql refuses `Target Session Attributes` with a single host in a connection string, before connecting ([`NpgsqlConnectionStringBuilder.cs`, lines 1508-1514](https://github.com/npgsql/npgsql/blob/d3768398c17877b3a916c3c4d87e8e11698991fc/src/Npgsql/NpgsqlConnectionStringBuilder.cs#L1508-L1514)). Several hosts go in `Host`, as in `Host=writer-endpoint,reader-endpoint`. `BuildMultiHost()` builds a data source on them, and `WithTargetSession` derives a data source for a role from it. According to [multiple hosts and failover](https://www.npgsql.org/doc/failover-and-load-balancing.html), Npgsql "detects whether a server is a primary or a standby by occasionally querying `pg_is_in_recovery()`", and checks again every `Host Recheck Seconds`, 10 by default.
- pgjdbc accepts a single host and checks the server's role when it connects: `targetServerType=secondary` finds no standby, SQLSTATE `08001`. Several hosts go in the URL, `jdbc:postgresql://writer-endpoint,reader-endpoint/learn`.
- Both find no standby on the local primary, and both fall back to it with `prefer-standby` and `preferSecondary`.

On Aurora, the reader endpoint already points to the replicas, and a separate data source for each endpoint is the simplest design. Role-based selection is useful when both endpoints are in one connection string, and during a failover, when the reader endpoint "might direct connections to the new primary DB instance", in the words of the [endpoints page](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Overview.Endpoints.html). Whether an Aurora Replica answers `pg_is_in_recovery()` with true, as a PostgreSQL standby does, is *to verify*.
