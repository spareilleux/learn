# Value of a renderer pilot, trial identity and decision horizon

This packet supports FUT005, CYB007 and PM006. It contains fixed authored decision calculations and primary-source interpretation, not a live pilot, production policy or new runnable lab. All loss points, likelihoods, priors and costs are explicit teaching premises.

## What the packet contains

- `production-plan.md` records predictions and publication gates before calculation.
- `primary-readback.json` binds four anonymous public GA document downloads at `76efbffd5af82b46c3146957a6bd4504008eeb89`, each equal to its immutable local Git object. The historical run headers have separate revisions and dirty-state context. These files do not calibrate the model.
- `primary-reading.json` records the actual MIT perfect/imperfect-information and NIST Bayes reading. The local MIT PDF page 10 was also visually read; its inequalities do not require information value to be strictly positive. No unrelated numerical medical or gambling example is imported.
- `pilot-decision.json` states the complete binary condition, action losses, likelihoods, tie rule and test cost. A noisy signal has gross value 1 and net value 0.4 here; perfect information has gross value 2 in that no-migration problem. A locked action set can make gross decision value zero.
- `belief-updates.json` enumerates 15 sequences of fresh observations through length 3, plus a ledger containing a copied report of one trial. Fresh-trial independence is conditional on the same stable latent state and must be stipulated or justified. Neither wrapper identity nor hash equality alone establishes the appropriate dependence model. Conditional optional second-trial values are separate from required validation obligations.
- `decision-horizons.json` reoptimizes after adding a one-time migration charge, rather than reusing the prior policy. At horizon 1 the positive branch ties, keeps K and pays no migration; the first positive net pilot value occurs at integer horizon 2. Information reuse requires a stable and relevant decision problem across the horizon.
- `source-observations.json` preserves historical-versus-calibrated, trial-versus-summary, unit and methodology boundaries.
- `data-audit.json` independently recomputes the exact arithmetic and verifies source bindings. `learner-task.md` and `reviewer-rubric.json` prepare transfer work; `content-audit.json` records independent review once completed, not actual learner performance.

## Publication and implementation boundaries

No new probe, graphics host, agent replacement, Bayesian controller, scene, quality judgment or production rollout was run. No real resource/time/cost saving or empirical likelihood is claimed. A typed decision record is a simpler candidate than a new DSL; neither is implemented by this packet.

`validation.json` records the completed local generator tests, source sync, full site build, changed article links and repeat-sync equality. An ordinary push plus anonymous immutable GitHub byte readback publishes source/evidence/generated files in Draft PR 201. Deployed HTML, human technical, fluent-language and learner reviews, real calibration and live outcomes remain separate pending gates. Original source provenance and journals are preserved.
