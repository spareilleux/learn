# Independent course and model-test review

Scope: the assigned unit only, after author freeze. Source existence and author self-checks are inputs; they are not an independent pass. Other review units run concurrently with disjoint source prefixes. Root alone executes authoritative integrated tests, updates shared files and commits.

Read every assigned EN/FR/ES lesson, all five questions and corrected answers, the actual prerequisite passages, and the fixed-data model/control packet. Check novelty against actual prior art, units/algebra/assumptions, source reading scope and version pins, translation meaning and numeric/code/URL parity. Read primary references actually needed to settle uncertain claims; a successful URL fetch alone is not a content review. Preserve source access failures and body-reading fallback limits. Technical, fluent-language, craft/musician and learner acceptance remain null; this is independent AI review.

Create one narrow standard-library Python test file `tests/test_unit_<unit>.py`, reading the actual `unit-<unit>.json` values and checking meaningful course claims using independent fixed expectations. Do not merely copy an expected field into the observed value. Every assigned course needs both a model and a relevant negative-control observation, printed as one JSON line prefixed `OBSERVATION ` before assertion. Records need code, case (`model` or `negative`), observed, expected and finite-model scope. Assert independently fixed values as well as consistency with the packet; use explicit rational/numeric tolerances. Domain cases may use several assertions, but no broad production validator or unrelated edge-case suite is requested. The previous batch's tests are patterns and regression context; do not edit them.

Execute only your focused test with Python -X utf8 -B, writing a unique full log/receipt outside the repository. Record actual command, Python version, exit, test/observation counts and exact input/test hashes. Root will independently replay the integrated final files. Demonstrate at least one substantive incorrect in-memory input is rejected, with its computed observation retained, without modifying canonical data or pretending a deliberate mutant rejection is a failing course. Preserve the original failed output if you find an actual course/test/helper defect. Fix only your owned new source prefixes/tests and review file, and report what changed; root coordinates author corrections when needed. Never update shared manifests, global journals or generated output.

Write `review-<unit>.json`: unit; verdict; coverage {courses,localized_sources,exercise_answer_pairs,learner_criteria}; course_checks [{code,decision,reasoning}]; exercise_answer_checks [{code,locale,exercise:1..5,decision,checked_result,reasoning}]; learner_criterion_checks [{code,criterion:1..5,decision,learner_decision:null,acceptance_reasoning}]; calculation_checks as a flat array with exactly two entries per course, each {code,case:"model" or "negative",observed,expected,pass_:true or false,method,scope}; findings with status `resolved` or `observed-preserved` only when justified; source_bindings for every final locale path/SHA256; supporting_bindings for actual packet/self-check/test/immutable protocol and other read inputs; prerequisite_bindings for actual baseline sources; focused_test_run and mutation_probe paths/hashes/scope; review limitations. Preserve before/after finding history. Bind only actual final bytes; mutable root journals, inventories, generated manifests and final validation receipts are excluded from supporting bindings.

Read actual complete statements; do not generate a Cartesian list of `pass` rows from a structural counter without inspecting answers and criteria. If a correctness issue remains unresolved, report it and keep verdict fail. Root must not ship a false green. Any change after a review needs affected bindings and checks renewed before publication.
