# Voice-leading characterization and music-course plan

## Guitarist question

When an agent says that a voicing is close to another, which differences did it ignore, and did its scalar comparison preserve the intended relation? A player may need an actual melodic path or a playable string assignment. A pitch-collection score alone need not contain either.

## Assumptions, counterargument and rejection criteria

The assumption is that these narrow native and exhaustive comparisons reveal a useful API boundary for music learners and agents. The strongest counterargument is that a manual example suffices; a teaching project adds SDK/annotation-adapter maintenance without improving understanding. Do not adopt a new DSL, ranking policy or general assignment algorithm on this result. Added graph or wrapper structure must earn its cost through a real learner task or consumer need. Keep unsupported claims about hearing, comfort, full application behavior, stability, performance, browser execution and cross-platform reproduction unassessed.

Native verification, source-assisted learner tasks, subject and fluent-language review, generated-page checks and eventual public HTML readback remain separate gates. This plan is not a human learning result or an external preregistration. The full525-course reviewed/published objective remains unchanged.
