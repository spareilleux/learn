Petri nets against other formalisms

The same net, written twice

  Nets.MutualExclusion() as a TLA+ module, generated by Examples/Tla.cs:

    ---------------------- MODULE mutual_exclusion ----------------------
    EXTENDS Naturals

    Places == {"idle1", "critical1", "idle2", "critical2", "mutex"}
    Transitions == {"enter1", "leave1", "enter2", "leave2"}

    PreArcs == {
        [p |-> "idle1", t |-> "enter1", w |-> 1],
        [p |-> "mutex", t |-> "enter1", w |-> 1],
        [p |-> "critical1", t |-> "leave1", w |-> 1],
        [p |-> "idle2", t |-> "enter2", w |-> 1],
        [p |-> "mutex", t |-> "enter2", w |-> 1],
        [p |-> "critical2", t |-> "leave2", w |-> 1]
    }

    PostArcs == {
        [p |-> "critical1", t |-> "enter1", w |-> 1],
        [p |-> "idle1", t |-> "leave1", w |-> 1],
        [p |-> "mutex", t |-> "leave1", w |-> 1],
        [p |-> "critical2", t |-> "enter2", w |-> 1],
        [p |-> "idle2", t |-> "leave2", w |-> 1],
        [p |-> "mutex", t |-> "leave2", w |-> 1]
    }

    M0 == [p \in Places |-> IF p \in {"idle1", "idle2", "mutex"} THEN 1 ELSE 0]
    \* Every place is bounded by 1 (Invariants.PlaceBounds), so the constraint truncates nothing.
    Cap == 1

    VARIABLE marking
    INSTANCE PetriNet
    =============================================================================

  The firing rule itself is not generated: tla/PetriNet.tla writes it once, by hand,
  and every module instantiates it. A marking is a function from places to naturals,
  so what TLC calls a state and what this course calls a marking are the same object.

What the model checker has to be told

  21 of 25 nets carry a cap the place invariants produced.
  The other 4 have no invariant covering every place, so the generated module caps them at 3:
    unbounded-producer
    handshake
    emit-loop
    handshake-started

  TLA+ has no notion of boundedness. Without a state constraint TLC enumerates until it
  runs out of memory; with one it stops and says nothing is wrong. The coverability tree
  of lesson 3 answers the question instead of avoiding it.

  * capped rather than bounded. Three of the four have no finite reachability graph, so
    the cap is the only thing that makes TLC stop. The fourth, handshake, has exactly one
    marking and is dead: a place invariant proves boundedness, it never disproves it.

  Steps that share a source and a target across the 21 bounded nets: 1.
  In order-sound, `ship` and `cancel` lead from one marking to the same one. A Petri net's
  graph is labelled by transitions and TLA+'s is not, so that step should have gone missing
  from TLC's count. It does not: TLC counts one state generated per disjunct it evaluates,
  not per successor it keeps, which is why 'arcs + 1' survives the collision.

What a net says that a specification does not

  mutual-exclusion            3 place invariants,  3 minimal siphons,  3 minimal traps
  philosophers-one-fork-3     6 place invariants,  7 minimal siphons,  6 minimal traps
  readers-writers             2 place invariants,  2 minimal siphons,  2 minimal traps

  None of these three numbers needs a reachable state. They are read off the arcs, which
  is why lesson 7's deadlock verdict survives a net whose state space nobody can build.

Against TLC

  Pass the directory of a TLC run to compare the two enumerations:
    dotnet run --project Examples -c Release -- tla out/tla
    java -cp tla2tools.jar tlc2.TLC -workers 1 -cleanup out/tla/mutual_exclusion.tla
  tla2tools.jar is at https://github.com/tlaplus/tlaplus/releases (MIT), and is not vendored here.
