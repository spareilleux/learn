## Course conventions

- The site has three locales. English is the source language (root locale, `src/content/docs/`); French and Spanish mirror it under `src/content/docs/fr/` and `src/content/docs/es/`, both with identical file names. Slugs (file names) are in English. Translate prose and the comments inside code blocks; code, commands and compiler or program output stay identical to the English page, and so do the link URLs.
- Each course folder: `index.md` (mission, prerequisites, plan, resources), numbered lessons `01-…md` with exercises and collapsible `<details>` solutions, and a dated `journal.md`.
- Order pages with `sidebar.order`; register each course as a collapsed `autogenerate` group in `astro.config.mjs`, nested under its area and sub-area groups, and list it under the same headings on all three home pages. *Software Engineering* / *Génie logiciel* / *Ingeniería de software* has three sub-areas: *Languages & frameworks* / *Langages et frameworks* / *Lenguajes y frameworks*, *Infrastructure & tooling* / *Infrastructure et outillage* / *Infraestructura y herramientas*, *AI-assisted development* / *Développement assisté par IA* / *Desarrollo asistido por IA*. Add a sub-area group only when its first course exists; keep the nesting at two levels.
- Mark anything not yet tested on the author's machine as *to verify* / *à vérifier* / *por verificar*, and cite primary sources.
- Code-heavy courses keep their code in `code/<course>/` (a Cargo project for Rust): runnable `examples/` plus `compile_fail` doctests for every snippet a lesson shows as rejected, run by `.github/workflows/rust-examples.yml`. Compile a snippet before quoting its output or error in a lesson, and paste the real output.
- `streeling/` (all locales), `src/streeling-sidebar.json` and `streeling.lock.json` are generated by `npm run sync:streeling` from GuitarAlchemist/Demerzel — never edit them by hand; change the script instead. Only `streeling/journal.md` is hand-written and preserved across syncs.
- The site is served under `base: '/learn'`: use relative links in Markdown (e.g. `../journal/`), never root-absolute `/…` links.
- Link the first mention in each lesson of a tool, product, library or named C#/Java/Rust API to its official documentation (learn.microsoft.com without locale, docs.oracle.com/openjdk.org, doc.rust-lang.org, docs.rs, the project's site). Check that every URL resolves before publishing.
- Support Windows, Linux/WSL and macOS. Where commands, paths or file names differ, use Starlight tabs in an `.mdx` lesson — `<Tabs syncKey="os">` with the labels `Windows`, `Linux / WSL` and `macOS`, in that order — so the reader's choice follows them across pages. Prose outputs captured on one OS are fine when only path separators differ. CI runs the course code on all three OSes.
- Diagrams are ```` ```mermaid ```` code blocks: `src/components/MarkdownContent.astro` replaces them with the rendered diagram in the browser (Mermaid from jsdelivr, pinned), and keeps the code block if a diagram doesn't parse. Their labels are prose: translate them in `fr/` and `es/`. Add one only where it explains more than the text around it.
- In `.mdx` files, prose must not contain bare `{`, `}` or `<` (JSX); keep them inside code. A fenced block that itself contains ``` needs a four-backtick outer fence.
- Claude artifacts (claude.ai/code/artifact/…) worth keeping are listed on `artifacts.md` (all locales) under the matching area, with their language, date and a short description, and linked from the courses they illustrate. Link only artifacts shared with anyone who has the link, and drop query strings such as `?via=…`.
- This repository is shared by several sessions: stage explicit paths only, right before committing (no `git mv` or `git add -A` ahead of time).

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.
